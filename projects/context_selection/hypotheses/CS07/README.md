# CS07 — сохранять оба потенциальных исхода при поиске контекста

**Вопрос:** помогает ли causal FM контекст, выбранный по двум слабым прогнозам потенциальных исходов, сильнее контекста, выбранного только по их разности?

**Основание:** CausalPFN оценивает `mu0(x)` и `mu1(x)` по отдельности, а описанная авторами эвристика для больших таблиц упорядочивает примеры по `tau_hat=mu1_hat−mu0_hat`. Разность не сохраняет уровень исходов. [Литературный разбор и границы новизны](../../../../docs/LITERATURE_POSITIONING.md).

**Основной контраст:** изменение преимущества двумерного CEPO-контекста над effect-score-контекстом при контролируемом увеличении вариации базового риска. Во всех условиях одинаковы исходные X/T, истинный CATE, шумовые uniform-числа, слабая модель, бюджет и treatment-баланс. Прямое локальное среднее по тем же соседям показывает, какая часть эффекта принадлежит самому retrieval.

**Статус:** [E01/v001](experiments/E01/v001.md) завершён как разведочная проверка. [Неизменяемый результат](results/E01/v001/20261019T230216_210188Z/README.md): предзаданный ориентир не выполнен. Interaction положителен в 4/5 генераций, но при переменном базовом риске CEPO улучшил PEHE и oracle regret@10% лишь в 3/5. Feature-kNN имел меньшую PEHE во всех пяти генерациях. Эта версия гипотезы не даёт основания переходить к большому benchmark CEPO.

Все десять случаев и 90 метрик независимо пересчитаны из сохранённых score; проверены исходы, истинный CATE, пять OOF-разбиений, баланс и уникальность 40 контекстов, SHA локальных файлов и снимка. Первый вызов упаковщика завершился после всех вычислений ошибкой дублирования `context_size`; незавершённые файлы архивированы в `artifacts/local/cs07_e01_packaging_failures/`, затем снимок собран из тех же score без нового FM-инференса. `code_git_commit` и `code_sha256` в снимке относятся к коду расчёта до технического исправления упаковщика.
