# CS07 / E01 / v001 — CEPO-контекст против effect-score-контекста

- **Статус:** plan. Код и протокол фиксируются до просмотра метрик. Owner: команда CS07.
- **Вопрос:** возникает ли преимущество CEPO-контекста над контекстом по слабой оценке CATE именно при сильной вариации базового риска, когда истинный CATE не меняется?
- **Данные:** пять независимых synthetic генераций с seeds `1901–1905`; каждая имеет 4096 train и 512 eval строк, восемь независимых `X_j ~ Uniform[-1,1]`, рандомизированное `T ~ Bernoulli(0.5)`. Истинный `tau(x)=0.05+0.07*x1+0.03*sign(x3)` (индексы с нуля), `p0(x)=0.30+a*0.15*x0`, `p1(x)=p0(x)+tau(x)`. Режимы `a=0` и `a=1` меняют только вариацию `p0`. Для обоих режимов использовать одни X/T и исходные Uniform(0,1) числа для двух бинарных потенциальных исходов; `Y=Y_T`. `tau`, строки и treatment остаются теми же. Проверить все вероятности до генерации outcome.
- **Предобработка и weak learner:** StandardScaler только на train-признаках. Один и тот же `GradientBoostingRegressor(n_estimators=100,max_depth=6,min_samples_leaf=max(2,n_fit//100),random_state=111)` с one-hot кодированным treatment `(X,1-T,T)` оценивает `mu0_hat` и `mu1_hat`. Для каждой train-строки обе оценки получить out-of-fold из пяти `StratifiedKFold` по `2*T+Y`, seed 42; eval-оценки — среднее прогнозов пяти моделей. Никакой истинный `tau` или eval outcome не используются в retrieval. Это та же архитектура слабого регрессора, что в закреплённом CausalPFN, но **query-wise** retrieval ниже не является точной репликацией авторского batch-window алгоритма.
- **Селекторы:** `K=512`, ровно 256 соседей из каждого treatment arm для каждого eval-query. `effect`: ближайшие по `tau_hat=mu1_hat−mu0_hat`; `cepo`: ближайшие по двум координатам `tau_hat` и `baseline_hat=(mu0_hat+mu1_hat)/2`, каждую делить на SD соответствующей out-of-fold train-координаты (одни шкалы для bank/query, floor `1e-6`); `feature`: ближайшие по стандартизированным X; `random`: независимый query-wise набор с seed `2900+generation_seed`. Один weak learner и один budget у `effect` и `cepo`; контексты проверять на уникальность/баланс. Для каждого контекста считать CausalPFN и прямую разность средних train-outcome в двух arms.
- **Модель:** неизменный CausalPFN checkpoint `vdblm/causalpfn` revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, temperature 1, без обучения или подбора на eval. Фиксированный HistGB S-Learner (`learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, seed 42) на тех же train-строках — дополнительный глобальный baseline.
- **Primary:** PEHE как RMSE предсказанного CATE против известного `tau`. Для каждого seed `D_a = PEHE(FM_effect,a) − PEHE(FM_cepo,a)` и interaction `D_1−D_0`. Положительное значение означает, что добавление информации о базовом риске стало полезнее при росте её вариации. Заранее заданный **описательный ориентир:** interaction положителен не менее чем в 4/5 генераций; при `a=1` `D_1>0` не менее чем в 4/5; oracle regret@10% у FM_cepo ниже FM_effect не менее чем в 4/5. Если хотя бы одно условие не выполнено, гипотеза в этой постановке не поддержана. Показать также сравнение с FM_feature, FM_random и прямым local на каждом контексте. Отдельно считать FM-специфичный выигрыш `D_a−[PEHE(local_effect,a)−PEHE(local_cepo,a)]`: если он не положителен, эффект нового отбора нельзя приписывать FM. Для дальнейшей статьи потребуется преимущество и над feature-kNN; победа только над effect-selector недостаточна.
- **Неопределённость:** показать все пять парных interaction, среднее/медиану и разброс; generation seed — единица повторения. Bootstrap eval-строк условен и не заменяет новых DGP. Режимы одного seed парные и не независимы. Не объявлять статистическую значимость по пяти генерациям. Результат синтетический и не доказывает улучшения на маркетинговом RCT.
- **Архив:** сохранить X/T, шумовые uniform-числа, истинный tau, weak scores, индексы контекста, полные score и статусы в `artifacts/local/cs07_e01_results/`. Компактный неизменяемый результат с метриками, парными эффектами, SHA входных/выходных файлов и code Git/SHA — в `results/E01/v001/<run-id>/`. Старые снимки не менять; при сбое пометить случай `incomplete`.
