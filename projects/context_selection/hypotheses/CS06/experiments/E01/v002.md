# CS06 / E01 / v002 — точная сериализация локальных score

- **Статус:** plan; исправление представления результатов v001, без новых данных и без нового FM-инференса. Все eval-outcome v001 уже просмотрены. Это **не независимый повтор**.
- **Причина новой версии:** Q̂ v001 считалась из точных `float64` значений локального среднего в памяти. Запись `predictions.csv` округлила некоторые почти равные значения `local_natural`, из-за чего повторный Q̂ из CSV меняется (например, когорта 413: `0.0377015067` из точного score против `0.0378653418` из CSV). Исходные `context_rows_*.npy` и train-outcome позволяют восстановить точные score. По правилам репозитория исправление ошибки хранения оформляется новой версией; v001 остаётся неизменным.
- **Источник:** неизменяемый снимок `CS06/E01/v001/20261019T185002_258957Z` и три локальных запуска `413–415`. Проверить SHA всех исходных файлов, source parquet, train/eval ID, T/Y, размеры и лечение в каждом контексте. Использовать сохранённые `partial_fm_*.npy` как точные FM-score; CausalPFN повторно не запускать. Для каждого контекста вычислить `mean(Y_train, treated neighbours) − mean(Y_train, control neighbours)` в `float64` и сохранить `.npy` без десятичного округления. S-Learner остаётся вторичным сохранённым score.
- **Метрики и uncertainty:** повторить исходный метод Q̂, AUUC, uplift@10%, три разности и 500 парных bootstrap resamples на когорту с теми же seeds `12000+sample_seed`. Пересчитанные результаты должны совпасть с v001 (допуск `1e-12`); при несовпадении остановиться и не упаковывать снимок. Primary interaction и заранее заданный описательный ориентир **не меняются**.
- **Результат:** новый неизменяемый снимок `results/E01/v002/<run-id>/` с `manifest.supersedes`, причиной замены, хешами исходов и точных `.npy`, протоколом, метриками и ограничениями. v001 не удалять. Статус `complete_exploratory` только после сверки всех трёх когорт. Условные интервалы и один Criteo-источник по-прежнему ограничивают вывод.

Команды: `.venv/bin/python tools/package_cs06_e01_v002.py --check` проверяет исходники и хеши; `.venv/bin/python -u tools/package_cs06_e01_v002.py package` создаёт точные score и снимок. Код/протокол сначала фиксируются Git-коммитом; после упаковки нужен независимый аудит и отдельный коммит результата.
