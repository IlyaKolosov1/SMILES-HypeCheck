# CS06 / E01 / v001 — arm allocation в feature-контексте

- **Статус:** plan. Owner: команда context selection. Код и протокол фиксируются Git-коммитом до чтения новых eval-outcome.
- **Мотивация:** ранее feature-контекст улучшал Q̂ относительно случайного и у FM, и у прямого локального метода, но добавочная ценность FM была неоднородной. Здесь меняется только число соседей каждого treatment arm. Разность эффектов FM и локального среднего проверяет, влияет ли состав контекста на FM сверх изменения простой локальной оценки.
- **Источник:** Criteo-ITE-v2.1, `visit`, три новые непересекающиеся 200 000-строчные выборки `413–415` после исключения всех предыдущих выборок до `412` включительно; split seeds `123–125`, train 51 200, eval 16 384, групповой split по идентичным признакам. Один исходный RCT остаётся ограничением вывода.
- **Контексты:** train-only preprocessing из CS01, Евклидовы feature-kNN отдельно в каждом arm, одинаковые признаки и `K=512`. `balanced`: 256 control + 256 treated. `natural`: `round(512 × train-control-rate)` control и остальные treated, фиксируется отдельно по когорте **до просмотра eval-outcome**; не менее 64 строк каждого arm. Соседи каждого arm берутся в том же порядке, поэтому различается лишь выделенный arm budget. Выходы FM считаются по обоим наборам соседей, локальный score — разность средних бинарного train-outcome между arms. Закреплённый CausalPFN checkpoint и CPU, без обучения FM.
- **Primary:** Q̂ (`normalized_qini_auc`) и interaction `(FM_natural − FM_balanced) − (local_natural − local_balanced)` на одинаковых eval-строках. Отдельно показать FM и local natural−balanced. Направление заранее **не фиксируется**: это тест чувствительности FM к allocation, а не обещание улучшения. Описательный ориентир для дальнейшего теста: interaction одного знака во всех 3 когортах, абсолютная средняя величина не менее `0.02` Q̂ и условный парный bootstrap-интервал средних не пересекает ноль. Это не критерий статистического подтверждения на независимых датасетах.
- **Secondary:** абсолютные Q̂, AUUC, uplift@10% и фиксированный S-Learner на том же train/eval. Ни одну конфигурацию не выбирать по eval и не менять allocation после результата. Если FM побеждает local только при одной доле, это не доказывает причинный механизм pretraining или переносимость на другие задачи.
- **Неопределённость:** 500 общих для четырёх методов resamples eval-строк внутри каждого treatment arm, seed `12000+sample_seed`; равновесное среднее трёх когорт и условный 95% percentile-интервал из средних bootstrap draws. Повторное обучение, выборка из новых датасетов и зависимость когорт от одного Criteo-источника не входят в эти интервалы.
- **Хранение:** полные предсказания, контексты, ID и исходные файлы — только `artifacts/local/cs06_e01_results/`; один компактный неизменяемый снимок `results/E01/v001/<run-id>/` с протоколом, SHA входов и выходов, Git/SHA кода, метриками, разностями и статусом. При сбое отдельный запуск остаётся `incomplete`; seed не подменяется.

Команды из корня репозитория: `.venv/bin/python tools/run_cs06_e01.py --check`; `.venv/bin/python tools/run_cs06_e01.py --smoke`; `.venv/bin/python -u tools/run_cs06_e01.py all`; `.venv/bin/python tools/run_cs06_e01.py --status`. `--check` сверяет исходные выборки и checkpoint без обучения, `--smoke` делает двухзапросный FM-вызов, `all` считает три когорты и упаковывает результат, `--status` показывает стадии и число сохранённых FM-предсказаний.
