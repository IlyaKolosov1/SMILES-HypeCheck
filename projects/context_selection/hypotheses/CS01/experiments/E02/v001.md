# CS01 / E02 / v001 — устойчивость feature-kNN на новых разбиениях

- **Owner:** исследовательская команда CS01. **Статус:** complete_exploratory; протокол и ориентир зафиксированы до просмотра результатов E02.
- **Вопрос:** сохраняется ли преимущество feature-kNN над query-dependent random context при новых outer split и context seeds на четырёх датасетах?
- **Primary контраст:** `feature_knn_K512 − mean(random_query_s201_K512, random_query_s202_K512, random_query_s203_K512)` по метрике Q̂ (`normalized_qini_auc` в CSV). Сначала разность внутри датасета и split; затем средняя разность и число положительных split внутри датасета. `effect_knn` с тем же baseline — вторичный контраст. Uplift@10%, AUUC и runtime — дополнительные описательные показатели.
- **Заранее заданный ориентир:** датасет поддерживает гипотезу, если его средняя разность Q̂ положительна и минимум два из трёх split положительны. Переносимость в этом разведочном эксперименте наблюдается, если таковы минимум три из четырёх датасетов. Это правило не является тестом статистической значимости.
- **Данные/outcomes:** Hillstrom `visit`, Retailhero-uplift `Y`, LZD `Y`, Criteo-ITE-v2.1 `visit`; Orange исключён до аудита семантики. Для Criteo используется новая равномерная 100k source sample в каждом запуске. Исходные SHA данных и аудит treatment/outcome сохраняются по датасету.
- **Разбиения:** три отдельные one-split запуска: `(split seed, Criteo sample seed) = (101,301), (102,302), (103,303)`. Context seeds `201,202,203` одинаковы во всех трёх запусках. Train bank ≤51 200, eval ≤4096; LZD и Criteo разделяются по группам одинаковых feature vectors. Новые seeds выбраны до просмотра E02 и не заменяются по результату.
- **Метод:** CausalPFN `vdblm/causalpfn` revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, `K=512` (256 строк на arm), query-dependent random, feature-kNN и effect-kNN с общими train/eval IDs. Для effect-kNN weak scores обучаются out-of-fold с пятью inner folds и nuisance seed `42`; preprocessing обучается только на train. Weak learner и shared random остаются диагностическими методами runner.
- **Неопределённость:** 500 парных bootstrap выборок eval-строк с сохранением treatment arms внутри каждого split; 95% percentile интервалы условны на fitted model, контекстах и этом split. Context seeds усредняются внутри split, не считаются репликациями. Три split на одних исходных данных зависимы. Для Criteo split и source sample меняются вместе. Общий p-value не вычисляется.
- **Код:** [runner](../../../../src/multi_dataset_context.py), Git SHA и SHA-256 скрипта фиксируются в снимке. Три запуска из корня репозитория с `--run --datasets Hillstrom Retailhero-uplift LZD Criteo-ITE-v2.1 --folds 1 --context-sizes 512 --context-seeds 201 202 203 --effect-score-mode crossfit --nuisance-folds 5 --nuisance-seed 42 --bootstrap 500 --device cpu --revision 83aad07da1cb077cfda4236878a1b07dc9f72a54`; для каждого добавляются соответствующие `--split-seed`, `--criteo-sample-seed` и `--out-dir artifacts/local/cs01_e02_results/split_<seed>`.
- **Команда запуска:** из корня репозитория выполните `.venv/bin/python -u tools/run_cs01_e02.py 101` (аналогично `102` и `103` в отдельных терминалах). Launcher лишь подставляет параметры выше и показывает progress bars runner; каждый повтор создаёт новый timestamped run ID. Вариант `.venv/bin/python -u tools/run_cs01_e02.py all` запускает три seed последовательно в одном терминале. Прерванные локальные попытки не объявляются завершёнными и не перезаписываются.
- **Бюджет и вывод:** примерно четыре часа CPU и около 1.5 ГБ локальных файлов. Полные предсказания и IDs остаются в `artifacts/local/`; компактный снимок исследования находится в `results/E02/v001/<run-id>/`. При сбое запуск сохраняется как `incomplete`; выборочно не заменяем seed и не выдаём частичный набор за полную проверку.

**Вывод:** заранее заданный описательный ориентир выполнен на 3/4 датасетов. На Hillstrom средняя ΔQ̂ отрицательная, поэтому универсального улучшения нет. Самая выраженная разность — на Criteo; random baseline там в среднем отрицательный (−0.0193), feature-kNN положительный (+0.1423). Для первичного контраста только один из 12 условных bootstrap-интервалов целиком выше нуля (Criteo, split 102); остальные пересекают ноль. Победы над девятью отдельными context seeds — диагностический срез, а не девять независимых повторов.

Вторичный `uplift_10_pp` для feature-kNN относительно среднего random context: Hillstrom −1.02 п.п., Retailhero +2.95 п.п., LZD −0.05 п.п., Criteo +5.17 п.п. Поэтому рост Q̂ на LZD пока не означает заметного улучшения в верхних 10% ранжирования; этот срез шумный и не был primary-критерием.

**Границы:** split на Hillstrom, Retailhero и LZD используют общие исходные строки; bootstrap фиксирует обученную модель и выбранные контексты. На Criteo вместе менялись source sample и split, так что их вклады не разделены; в eval каждого Criteo split лишь 24–27 положительных исходов в control arm. Статистическую значимость общего эффекта и превосходство над классическими uplift-моделями этот эксперимент не устанавливает.

В анализ вошли только три завершённых запуска выше. Предыдущие локальные попытки, остановленные до окончания Hillstrom, не включены и не выдаются за результаты.
