# CS01 / E06 / v001 — внешний Udacity/Starbucks RCT

- **Статус:** plan. Протокол выбран до первого CausalPFN-инференса и просмотра метрик моделей на этих данных. Проверяет переносимость основного CS01-контраста на ранее не использованный источник; выбор feature против random основан на CS01/E03–E05, а не на результате CS04/E02.
- **Источник:** официальные `training.csv` и `Test.csv` [Udacity Starbucks exercise](https://github.com/udacity/DSND_Term2/tree/master/portfolio_exercises/Experiments), аудит и SHA в [общем документе](../../../../../../docs/EXTERNAL_DATA_AUDIT.md). Использовать все 84 534 train и все 41 650 test строк без ресемплинга; `ID` лишь для проверки парности, `Promotion=Yes` означает treatment, `purchase` — бинарный outcome. Никакие test labels не входят в preprocessing, выбор контекста или настройку.
- **Признаки:** `V1,V4,V5,V6,V7` считать категориальными и кодировать one-hot; `V2,V3` стандартизовать. Все преобразования fit только по официальному train, `handle_unknown=ignore`. Одинаковые 18 преобразованных координат используются для расстояния и на входе FM. Значения `ID`, `Promotion`, `purchase` в признаки не входят.
- **FM и контекст:** CausalPFN `vdblm/causalpfn`, revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, `calibrate=False`, `K=512`. В каждом контексте 256 control и 256 treated, без повторов. `feature_knn` выбирает ближайших по евклидову расстоянию в 18 признаках, отдельно по arms. `random_query_s1101/s1102/s1103` выбирают независимый случайный контекст для каждого test-запроса, отдельно по arms. Train bank и test строки одни и те же для всех четырёх вариантов.
- **Primary:** Q̂ (`normalized_qini_auc`) на **всех 41 650 test строках**; `Δ = Q̂(feature_knn) − mean_s Q̂(random_query_s)`. Усреднять три значения метрики, а не три score-вектора. Заранее заданный описательный ориентир: `Δ > 0`; более сильное условное свидетельство — нижняя граница 95% парного bootstrap-интервала выше нуля. Если ориентир не выполнен, переносимость преимущества feature-селектора на этот RCT не подтверждена.
- **Secondary:** нормализованный AUUC, uplift@10%, Q̂ `feature_knn −` прямое локальное среднее outcome по **тем же** 256+256 соседям, и такой же контраст для random контекстов. Для прямого среднего показывать долю связанных scores (ties), поскольку outcome редкий. Эти сравнения не заменяют primary, а их интервалы не объявлять подтверждающими.
- **Неопределённость:** 1000 парных bootstrap выборок из test с сохранением размера каждого treatment arm, seed `1104`. Интервалы условны на фиксированных train, test, context seeds и коде; один RCT не даёт оценки вариации между кампаниями. Не выбирать удачный context seed после просмотра результата.
- **Хранение и проверка:** до инференса проверить SHA обоих CSV и checkpoint, 126 184 уникальных и непересекающихся `ID`, отсутствие пропусков, treatment/outcome клетки, преобразование и 18-мерный вход. Сохранить test ID, T/Y, полные scores, точные train IDs контекстов, прогресс и статус в исключённом из Git `artifacts/local/cs01_e06_results/`. Компактный неизменяемый снимок `results/E06/v001/<run-id>/` содержит протокол, метрики, парные разности и условные интервалы, SHA входов/выходов и копии кода. Прерванный запуск оставить `incomplete`.

Код и протокол должны быть зафиксированы Git до полного расчёта. Запускать `.venv/bin/python -u tools/run_cs01_e06.py --check`, затем `.venv/bin/python -u tools/run_cs01_e06.py --smoke`, затем `.venv/bin/python -u tools/run_cs01_e06.py all`; состояние смотреть `.venv/bin/python tools/run_cs01_e06.py --status`.
