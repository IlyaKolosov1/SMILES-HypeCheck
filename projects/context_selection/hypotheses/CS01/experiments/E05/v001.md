# CS01 / E05 / v001 — повторная проверка на отдельных LZD train banks

- **Статус:** plan. Этот протокол и код фиксируются в Git до расчёта Q̂ для новых eval-групп. E05 продолжает положительный E04, поэтому выбор LZD и метода уже зависел от прошлых результатов.
- **Вопрос:** остаётся ли преимущество feature-контекста при одновременной смене eval-строк, train bank и seeds случайного контекста?
- **Данные:** тот же LZD `T → Y` и те же очищенные `f*` признаки, что в E04. Зафиксировать SHA `features.parquet`, `outcomes.parquet`, `cleaning_metadata.json` и checkpoint CausalPFN `vdblm/causalpfn`, revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`. CPU.
- **Исключение старых eval:** [список 13 файлов и SHA](v001_prior_eval_sources.csv) включает 12 источников E04 и завершённый E04 `eval_rows.csv`. Объединить их `source_row` и исключить все feature-группы этих строк из новых eval-кандидатов. Для выбора не использовать их или новые outcomes.
- **Три заранее заданные когорты:** среди оставшихся feature-групп взять первую исходную строку каждой группы, затем выбрать 24 576 представителей без замены `np.random.default_rng(801).choice(...)`. Последовательные части по 8192 строк — когорты 1–3. Из всех остальных feature-групп взять по одному представителю; выбрать 153 600 строк без замены `np.random.default_rng(802).choice(...)` и разделить на три train bank по 51 200. Когорте `i` соответствует train bank `i`. Все шесть наборов не пересекаются ни по строкам, ни по feature-группам. Старые eval-группы можно использовать в train, но не в новых eval. Если кандидатов не хватает или в когорте отсутствует ячейка `T × Y`, оставить запуск `incomplete`, seeds не заменять.
- **Методы:** для каждой когорты отдельное train-only преобразование признаков и одна и та же закреплённая CausalPFN. `feature_knn_K512` против трёх query-dependent `random_query_s901/s902/s903_K512`; каждый контекст содержит 256 control и 256 treated train-строк. Seeds случайного контекста новые относительно E03/E04. Другие селекторы и модели здесь не считать.
- **Primary:** Q̂ (`normalized_qini_auc`). В каждой когорте `Δ_i = Q̂(feature_knn) − mean_s Q̂(random_query_s)`; усреднять **метрики**, не scores. Итог — равновесное среднее трёх `Δ_i` и число положительных когорт. Заранее заданный **описательный ориентир:** среднее > 0 и 3/3 когорты с `Δ_i > 0`. Если хотя бы одно условие не выполнено, устойчивость к смене train bank по этому ориентиру не подтверждена.
- **Дополнительно:** абсолютные Q̂, нормализованный AUUC, uplift@10% и ячейки `T × Y` каждой когорты. Для каждой `Δ_i` посчитать 500 парных bootstrap выборок eval-строк с сохранением размера treatment arms, seeds `831`, `832`, `833`, и 95% percentile интервалы. Они условны на когорте и уже обученных scores; три когорты из одного LZD не дают формального общего p-value. Сводный интервал из этих bootstrap не выдавать за неопределённость между датасетами.
- **Хранение и ресурс:** около часа CPU для `3 × 4 × 8192 = 98 304` FM-предсказаний. Полные scores, context IDs и source IDs — в исключённом из Git `artifacts/local/cs01_e05_results/`. Один компактный неизменяемый снимок внутри `results/E05/v001/<run-id>/` содержит протокол, метрики, парные разности, SHA входов/выходов и снимки кода. Любая прерванная попытка остаётся `incomplete`.

Из корня репозитория: `.venv/bin/python -u tools/run_cs01_e05.py --check` проверяет фиксированные ID, SHA, размеры наборов и checkpoint без инференса; `.venv/bin/python -u tools/run_cs01_e05.py` запускает все три когорты; `.venv/bin/python tools/run_cs01_e05.py --status` показывает текущую стадию. После запуска независимо пересчитать Q̂ из `predictions.csv`, проверить все SHA и `tools/validate_repository.py`, затем обновить этот протокол и README гипотезы.
