# CS01 / E04 / v001 — feature-контекст на новом eval-наборе LZD

- **Статус:** plan. Протокол записан до расчёта Q̂ для выбранного ниже holdout. LZD выбран после просмотра E01/E02, поэтому исследование проверяет переносимость сигнала Criteo на второй источник, но не является слепым выбором датасета.
- **Вопрос:** сохраняется ли преимущество CausalPFN с feature-kNN перед query-dependent random-контекстом на строках LZD, которые не входили в ранее сохранённые eval-наборы?
- **Данные:** LZD, treatment `T`, benefit outcome `Y`, очищенные `f*` признаки из `artifacts/local/data_A_cleaned/LZD/`. Проверять SHA `features.parquet`, `outcomes.parquet` и `cleaning_metadata.json`, бинарность `T/Y` и точный порядок `source_row`. CausalPFN checkpoint `vdblm/causalpfn` revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU.
- **Исключение старых eval:** [зафиксированный список 12 локальных файлов](v001_prior_eval_sources.csv) содержит SHA и размеры всех доступных на момент планирования LZD `eval_rows.csv` из старых CS01 прогонов. Взять объединение их `source_row`, затем исключить **все feature-группы**, встречавшиеся среди этих строк. Это использует только ID и признаки для выбора новых eval, без исходов новых строк. Записать SHA объединения и SHA списка новых eval IDs. Исторические ID-файлы имеют зафиксированный текущий SHA, но не каждый из них был захеширован в старом компактном снимке; границу аудита отразить в выводе.
- **Фиксированный split:** из оставшихся feature-групп взять по одной строке-представителю каждой группы, выбрать 24 576 строк без замены генератором `np.random.default_rng(701)` и оставить порядок генератора. Первые, вторые и третьи 8192 строки образуют три диагностических eval-блока. Общий train bank из 51 200 строк выбрать без замены генератором `np.random.default_rng(702)` из всех остальных исходных строк, исключив feature-группы всех eval-строк. Ни train/eval строки, ни их feature-группы не пересекаются. Train bank один для всех методов и eval-блоков. Если не хватает строк или одна из четырёх ячеек `T × Y` пуста, пометить запуск `incomplete` и не заменять seeds.
- **Методы:** CausalPFN с `feature_knn_K512` и тремя `random_query_s201/s202/s203_K512`, каждый контекст строго 256 control + 256 treated train-строк. Признаки и преобразования для FM обучать только на train. Модель, train bank, K и eval ID одинаковы для четырёх методов. Другие селекторы и классические модели не вычислять.
- **Primary:** на **всех 24 576 eval-строках вместе** Q̂ (`normalized_qini_auc`) и парная разность `Q(feature_knn_K512) − mean_s Q(random_query_s_K512)`. Усреднять значения метрик трёх random seeds, а не scores. Заранее заданный **условный ориентир**: разность положительна, её 95% парный bootstrap-интервал целиком выше нуля и минимум 2/3 диагностических eval-блоков имеют положительную разность. При невыполнении любого пункта считать подтверждение на LZD не полученным.
- **Неопределённость и дополнительные метрики:** 500 парных bootstrap выборок eval-строк с сохранением числа строк в каждом treatment arm, seed `703`; 95% percentile интервал условен на фиксированном train bank, модели, контекстах и holdout. Показать Q̂ каждого метода, AUUC, uplift@10%, частоты `Y=1` по arm, разности по трём блокам и runtime. Блоки не являются независимыми тренировочными повторами: train bank общий. Положительный результат относится к LZD при этом протоколе, а не к универсальному эффекту FM.
- **Ресурс и хранение:** около часа CPU для 98 304 FM-предсказаний (`4 × 24 576`) плюс загрузка и bootstrap. Полные предсказания, context IDs и train/eval IDs — в `artifacts/local/cs01_e04_results/`; компактный неизменяемый снимок с SHA входов, кода и выходов — в `results/E04/v001/<run-id>/`. Прерванную попытку не выдавать за результат.

Команды из корня репозитория: `.venv/bin/python -u tools/run_cs01_e04.py --check` проверяет исходные SHA, ID и локальный checkpoint без FM-инференса; `.venv/bin/python -u tools/run_cs01_e04.py` выполняет расчёт и упаковку.
