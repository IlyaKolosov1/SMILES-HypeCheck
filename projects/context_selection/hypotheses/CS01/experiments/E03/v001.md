# CS01 / E03 / v001 — Criteo: новый контекст против random и X-Learner

- **Статус:** complete_exploratory. Протокол зафиксирован до чтения outcome новых выборок. Это прицельная проверка сигнала CS01/E02 на Criteo, выбранного после просмотра старых результатов; вывод относится к Criteo, не ко всем датасетам.
- **Вопрос:** сохраняется ли выигрыш CausalPFN с feature-kNN над случайным query-контекстом на новых строках? Может ли этот вариант быть конкурентным с фиксированным X-Learner на тех же train/eval-строках?
- **Данные:** `artifacts/local/data_A_cleaned/Criteo-ITE-v2.1/{features,outcomes}.parquet`, treatment `T`, benefit outcome `visit`, десять очищенных `f*` признаков. Проверять SHA обоих parquet и `cleaning_metadata.json`. Исходные позиции строк (`source_row`) служат идентификаторами, а не значения `epk_id` для обучения.
- **Новые выборки:** из 13 979 592 исходных строк исключить полные 100k source samples со старыми seeds `42`, `301`, `302`, `303`, восстановленные тем же `np.random.default_rng(seed).choice(total, 100000, replace=False)`. Затем последовательно выбирать по 100 000 строк без замены из оставшегося множества с sample seeds `401`, `402`, `403`, каждый раз исключая выбранные строки. Это три непересекающиеся выборки; их списки ID, SHA и отсутствие пересечения со старыми train/eval ID нужно сохранить и проверить. Взгляда на новый outcome при выборе строк нет.
- **Разбиения:** `(sample seed, split seed) = (401,111), (402,112), (403,113)`. Один group-safe split по одинаковым векторам признаков внутри каждой выборки; train bank 51 200, eval 8192. Для всех методов в выборке одинаковые train/eval IDs, `T` и `visit`. Преобразования признаков обучать только на train. Если событий в одной из четырёх ячеек `T × visit` нет, пометить запуск `incomplete`, seed не заменять.
- **CausalPFN:** `vdblm/causalpfn`, checkpoint revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, `K=512` с 256 train-строками каждого treatment arm. `feature_knn_K512` и три независимых query-dependent random-context варианта `random_query_s201/s202/s203_K512`. Остальные селекторы не вычисляются. Случайные seeds фиксированы, а не подбираются; усреднять **метрики**, не предсказания random-вариантов.
- **Классический ориентир:** X-Learner по той же реализации, что M01/E02, на тех же 51 200 train строках: `HistGradientBoostingClassifier` для исхода и `HistGradientBoostingRegressor` для pseudo-outcomes, `learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1.0`, `random_state=42`. Никакой настройки по eval.
- **Primary:** Q̂ (`normalized_qini_auc`), контраст `feature_knn_K512 − mean_s Q(random_query_s_K512)` внутри выборки. Затем сообщить среднюю разность и число положительных выборок. Заранее заданный **описательный ориентир**: средняя ΔQ̂ > 0 и 3/3 выборки с ΔQ̂ > 0. Это не формальный тест значимости.
- **Secondary:** Q̂-контраст `feature_knn_K512 − X-Learner`, абсолютные Q̂ всех методов, AUUC, uplift@10%, числа событий по treatment arm и время. Никакого переключения primary на X-Learner или выбора лучшего метода по eval. Если secondary контраст положителен, это только повод к следующей проверке.
- **Неопределённость:** 500 парных bootstrap повторов eval-строк с сохранением treatment arms внутри выборки и 95% percentile интервалы для двух Q̂-контрастов. Интервалы условны на выбранных данных и fitted scores. Три выборки не пересекаются по строкам, но приходят из одного датасета и одного checkpoint; обобщение на другие датасеты и общий p-value не заявляются.
- **Ресурс и вывод:** примерно 30–45 минут CPU на одну выборку и несколько сотен МБ локальных артефактов; скрипт печатает короткую строку каждые 10% этапа и оценку оставшегося времени. Исходные parquet и полные предсказания не копировать в Git. Каждый запуск сохраняет отдельную неизменяемую локальную папку в `artifacts/local/cs01_e03_results/`; после трёх завершённых запусков упаковщик создаёт компактный снимок `results/E03/v001/<run-id>/` с протоколами, исходными SHA, таблицами, SHA скриптов, Git SHA и ограничениями.

## Команды после проверки кода

Из корня репозитория: `.venv/bin/python -u tools/run_cs01_e03.py --check` (проверка исходных файлов, старых/новых ID и локального checkpoint без обучения). Затем `.venv/bin/python -u tools/run_cs01_e03.py 401`, аналогично `402` и `403`; либо `.venv/bin/python -u tools/run_cs01_e03.py all` для последовательного запуска. Ход работы во втором терминале: `.venv/bin/python tools/run_cs01_e03.py --status` (стадия и доля уже сохранённых предсказаний). Прерванный запуск остаётся отдельной папкой со статусом `incomplete`; новая команда создаёт новую папку. Упаковка после завершения: `.venv/bin/python -u tools/package_cs01_e03.py --check` и `.venv/bin/python -u tools/package_cs01_e03.py`. `--check` упаковщика должен требовать ровно по одному завершённому запуску на каждый seed; при нескольких завершённых запусках одного seed нужно явно выбрать нужные папки.

## Выполнение и результат

[Неизменяемый снимок](../../results/E03/v001/20261018T201230_193386Z/README.md) содержит исходные протоколы, SHA входных файлов и кода, полные таблицы метрик и условных интервалов, список 72 проверенных локальных файлов. Завершены три заранее заданные выборки `401`, `402`, `403` с соответствующими split seeds `111`, `112`, `113`; в каждой 51 200 train и 8192 eval строки. Все три запуска записали один Git SHA кода `ebcad7f`, совпадающие SHA исходных parquet и checkpoint, а упаковщик проверил порядок строк, непересечение выборок и train/eval, treatment/outcome, комплектность предсказаний и повторно вычислил Q̂. Команда `tools/package_cs01_e03.py --check` прошла: 3/3 выборки, 18 строк метрик, 36 строк парных метрик.

| Criteo sample seed | Feature Q̂ | Среднее random Q̂ | X-Learner Q̂ | Feature − random | Feature − X |
| --- | ---: | ---: | ---: | ---: | ---: |
| 401 | 0.1868 | 0.0019 | 0.0798 | +0.1849 | +0.1070 |
| 402 | 0.1352 | 0.0451 | 0.0375 | +0.0901 | +0.0977 |
| 403 | 0.0915 | 0.0382 | 0.0490 | +0.0533 | +0.0425 |
| Среднее | 0.1378 | 0.0284 | 0.0554 | **+0.1094** | **+0.0824** |

Primary описательный ориентир **выполнен**: средняя ΔQ̂ положительна и 3/3 выборки дали положительную разность. Secondary контраст с X-Learner также положителен в 3/3, но не был критерием успеха. Условный 95% bootstrap-интервал primary исключает ноль только для выборки 401 (`+0.0483…+0.3143`); для 402 и 403 он включает ноль. Все три интервала secondary включают ноль. Это свидетельство повторяемости направления на новых строках Criteo, но **не доказательство статистической значимости** и не вывод о других датасетах. Bootstrap не учитывает новое обучение, выборку или вариацию checkpoint; три выборки происходят из одного источника, а Criteo был выбран по предыдущим результатам.

Первая попытка для seed `401` была прервана из-за нечитаемого вывода progress bar. Её локальная папка осталась `incomplete`; seed не заменён, эта попытка не включена в снимок. После исправления только вывода расчёт начат заново с теми же предзаданными параметрами. Статус `reviewed` можно присвоить после независимой проверки участником хотя бы одного парного контраста.
