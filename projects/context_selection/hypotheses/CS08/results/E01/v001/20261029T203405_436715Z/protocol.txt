# CS08/E01/v001 — аудит исходного риска в сохранённых контекстах

**Статус до вычисления:** plan. **Дата протокола:** 2026-10-29. **Owner:** Илья
Колосов и исследовательская команда. Код и этот протокол коммитятся до расчёта.

## Вопрос и исходные данные

Проверить, содержат ли `feature_knn_K512` контексты разный прогноз исходного
риска в treated/control. Использовать только сохранённые ID строк из
[CS01/E02/v001](../../../CS01/experiments/E02/v001.md): Hillstrom,
RetailHero, LZD и Criteo, три разбиения `101–103`, `K=512`, по 4096 eval-строк
на случай. Сравнение: `feature_knn`, `effect_knn` и три `random_query` seeds
`201–203` на **тех же** train/eval и context IDs. Criteo source sample seeds
`301–303`. Outcome и признаки берутся из исходных `fold_config.json`; для
Criteo это `visit`.

## Оценка исходного риска

Построить отдельную диагностическую модель
`g0(x)=P(Y=1|T=0,X=x)`: `HistGradientBoostingClassifier` на control-строках,
`learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`,
`l2_regularization=1.0`, `random_state=42`. Пять внутренних folds по всему
train bank, стратификация по T×Y, seed `42`; на LZD/Criteo также разделить
одинаковые X по группам. Preprocessing каждого fold обучается только на его fit.
Каждую train-строку оценивать моделью, которая не видела ни её исход, ни её
группу совпадающих признаков. Предсказания на eval не нужны. Качество `g0`
проверить на out-of-fold control-строках по Brier skill против fold-specific
постоянной частоты. При отрицательном skill разности прогнозов считать
ненадёжной диагностикой.

Для каждого запроса/селектора взять **абсолютную** разницу средних OOF `g0`
между 256 treated и 256 control строками. Основной диагностический показатель
— среднее этого абсолютного разрыва в процентных пунктах по запросам, затем
среднее по трём разбиениям внутри датасета. Дополнительно сохранить медиану,
90-й процентиль, подписанную разность, долю запросов с разрывом ≥0.5 п.п.
и частоты контекстов без событий в arm. Среднее трёх random seeds показывать
как один baseline внутри split, не как три независимых наблюдения.

**Описательный gate для следующего метода:** минимум на двух из четырёх
датасетов Brier skill положителен во всех трёх разбиениях, а средний
абсолютный разрыв feature-контекста ≥0.5 п.п. Это масштаб, сопоставимый с
практически интересным изменением uplift порядка 1 п.п.; gate не является
статистическим тестом и не разрешает автоматически запускать FM. Если gate
не выполнен, парный селектор по этому конкретному `g0` не приоритетен.

## Целостность и вывод

Перед fit сверить SHA исходных parquet с CS01, source IDs train/eval и
предсказаний, непересечение разбиений, treatment/outcome, 512 уникальных
donor IDs и 256/256 arms для каждого запроса. Никаких eval labels для выбора
контекста или обучения `g0`. Полные query-level диагностики и OOF scores
хранить только в `artifacts/local/`; в Git — компактный неизменяемый снимок,
протокол, хеши входов/выходов, SHA кода и Git commit.

Это ретроспективная диагностика состава уже просмотренных контекстов, а не
подтверждение улучшения FM. Нет новых FM-предсказаний, парного селектора,
оценок uplift@10% или независимой кампании. Если gate пройден, новый алгоритм
и контраст с feature-FM, direct/adjusted local и классическим baseline
требуют отдельного заранее зафиксированного эксперимента.

## Ресурсы и команды

Расчёт: 12 случаев × 5 fit `g0`; оценка <4 часов CPU на текущей машине,
уточняется фактическим временем. Память: один датасет и пять массивов ID
контекста за раз; полный вывод — десятки МБ. GPU и веса CausalPFN не нужны.
Runner показывает общий прогресс, стадию и ETA; локальный `status.json`
обновляется после каждой стадии. Resume не реализован; прерванный run остаётся
`incomplete`, новый запуск получает новый ID.

Из корня репозитория:

```bash
.venv/bin/python -u tools/run_cs08_e01.py --check
.venv/bin/python -u tools/run_cs08_e01.py all
.venv/bin/python -u tools/run_cs08_e01.py --status
```

`--check` проверяет 12 комплектов входов без обучения; `all` выполняет аудит;
`--status` только читает последний локальный статус. `-u` сразу выводит прогресс.
