# CS04 / E02 / v001 — нужна ли локальному контексту доля разнообразия?

- **Статус:** plan. Протокол выбран после просмотра CS04/E01, но **до** генерации данных и просмотра метрик новых seeds `71–80`. Это внутренняя проверка на том же DGP, не внешняя валидация.
- **Мотивация:** в [E01](../E01/v001.md) поиск по всем 32 признакам снизил CATE RMSE относительно поиска только по 8 полезным при одинаковом 32-мерном входе CausalPFN, хотя соседи были дальше по истинному CATE. Проверяем возможную роль разнообразия без смены признаков, подаваемых в модель.
- **Данные:** прежний `three_groups_v1` с 8 полезными признаками и 24 независимыми `Uniform[-1,1]` шумовыми столбцами. Новые generated seeds `71–80`; каждый даёт 8192 train и 2048 eval строк. Генерация train/eval и шумовых столбцов через отдельные `SeedSequence` потоки. Истинный CATE используется только для анализа и оценки.
- **Общий бюджет:** закреплённая CausalPFN revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, `K=512`, по 256 treated и control в каждом контексте; весь вход модели — одни и те же 32 стандартизованных по train признака. Препроцессинг и train/eval IDs одинаковы у всех методов. Нет обучения слабого learner, подбора параметров или доступа к eval labels при выборе соседей.
- **Три контекста:** `local8` — 256 ближайших train-строк в каждом arm по первым 8 стандартизованным признакам; `mix50` — 128 ближайших в каждом arm и 128 случайных из оставшихся train-строк того же arm; `random` — 256 случайных в каждом arm. Для случайных частей использовать отдельные query-dependent потоки с seed `983`, не выбирать удачный seed после результата. Сохранить точные train indices, проверить отсутствие дублей и баланс arms. В `mix50` локальные 128 являются подмножеством `local8` для того же запроса.
- **Дополнительный ориентир:** `feature32` — 256 ближайших по всем 32 признакам в каждом arm, чтобы связать E02 с E01; он не входит в primary. Всего четыре inference-варианта на seed.
- **Primary:** `P = CATE_RMSE(local8) − CATE_RMSE(mix50)`; положительное значение означает, что добавление разнообразия снизило ошибку при одинаковом входе модели. Заранее заданный описательный ориентир: среднее `P > 0`, минимум 8/10 generated seeds с `P > 0`, и средняя `CATE_RMSE(random) − CATE_RMSE(mix50) > 0` (смесь должна быть практически лучше случайного контекста). Не заменять этот контраст после просмотра данных.
- **Secondary:** полные CATE RMSE, Q̂ (`normalized_qini_auc`) по observed outcomes, истинный regret@10%, средняя абсолютная разница CATE между query и соседями, внутриконтекстное SD истинного CATE и признаков, доля общих соседей, runtime. Q̂ и regret не объявлять подтверждёнными по primary RMSE.
- **Неопределённость:** единица повтора — independently generated dataset. Показать все десять `P`, 95% percentile bootstrap-интервал среднего по десяти seeds (10 000 resamples, seed `984`) и двусторонний точный sign-test. Eval-строки внутри одного seed не являются независимыми DGP-повторами. Итог касается одного DGP и не переносится автоматически на LZD/Criteo.
- **Хранение:** полные generated data, scores, контексты и SHA — в `artifacts/local/cs04_e02_results/`; компактный неизменяемый снимок `results/E02/v001/<run-id>/` с протоколом, всеми seed-level метриками, paired differences, Git/code/data SHA, статусом и ограничениями. Прерванный run пометить `incomplete` и не заменять заранее заданный seed.

Перед запуском проверить pinned checkpoint, `--help`, парность генерации, индексы контекстов и smoke-инференс четырёх вариантов. Запускать полную серию только после фиксации кода и протокола в Git; после завершения независимо пересчитать primary и метрики из предсказаний.
