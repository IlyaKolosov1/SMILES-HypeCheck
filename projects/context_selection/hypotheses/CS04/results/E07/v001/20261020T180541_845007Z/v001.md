# CS04 / E07 / v001 — раздельные признаки retrieval и входа CausalPFN

**Статус до score:** план. [E06](../../../E06/v001/20261020T171138_317614Z/README.md) прошёл дешёвый gate обнаружения признаков, но не измерял качество CATE. Этот протокол и код фиксируются до просмотра новых model score.

## Вопрос и позиционирование

При том же `K=512` улучшает ли **train-only** раздельный отбор признаков для поиска строк и для входа FM точность CATE **сверх** (a) полного входа/поиска, (b) одного и того же выбранного набора для обеих ролей, (c) глобального T-Learner? Достаточна ли точность для лучшего ранжирования политики при охвате 10%? [CausalPFN](https://arxiv.org/html/2506.07918v2) уже использует retrieval, а [MALTS](https://jmlr.org/papers/v23/21-0053.html) учит расстояние по outcome, поэтому само по себе обучение importance не ново. Возможный вклад — именно различие ролей двух пространств в causal FM, если оно выдержит сильные контроли.

## Новые данные и train-only gate

- Восемь seeds `311–318`; у каждого независимые train `8192` и eval `2048` из **новой функции** при 32 столбцах: четыре прогностических `P`, четыре модификатора эффекта `M`, 24 независимых шумовых. Сигнальные координаты коррелируют как `0.25^|i−j|`. Общая случайная перестановка 32 столбцов применяется к train/eval внутри seed и скрыта от selector. `T~Bernoulli(.5)`. `mu0=0.40sin(P0+P1)+0.25P2P3`; `tau=0.30tanh(1.5M0−0.5M1)+0.20sin(M2M3)`; `Y=mu0+T*tau+Normal(0,.4)`. Истинные τ и индексы доступны только для диагностики/оценки. Этот генератор выбран после E06, поэтому даже новые seeds не дают внешнюю независимую проверку метода.
- Повторить без настройки [E06 selector](../../../../experiments/E06/v001.md): inner fit/validation 75/25, отдельные HistGradientBoostingRegressor по arms, три permutation validation, top-8 по outcome-MSE importance для входа и top-4 по R-loss importance для retrieval. HGB параметры фиксированы: `learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, seed `42`. Все данные selector — только train этого seed.
- **Gate ресурса до FM-score:** в ≥6/8 seeds input top-8 должен содержать ≥6/8 настоящих `P∪M`, а retrieval top-4 — ≥3/4 настоящих `M` в ≥6/8. Скрытая истина здесь используется лишь как дешёвый synthetic resource gate. Если gate не выполнен, завершить E07 с таблицей отбора и статусом «FM не запускалась»; не менять метод или seeds в этой версии.

## Парное сравнение, если gate пройден

`StandardScaler` обучается только на train. Для каждого eval query искать ровно 256 ближайших train-строк **в каждом treatment arm**. После выбора подмножества столбцы в каждом входе/расстоянии располагаются по возрастанию исходного номера, а не по рангу importance. Пять CausalPFN cells на одних train/eval/outcome, checkpoint `vdblm/causalpfn` revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, `calibrate=False`, CPU 4 threads:

| Cell | Признаки retrieval | Признаки входа FM | Роль |
| --- | --- | --- | --- |
| `full_full` | все 32 | все 32 | исходный контроль |
| `full_input8` | все 32 | train-only top-8 outcome | изолировать вход |
| `shared8_input8` | top-8 outcome | те же top-8 | общий набор в двух ролях |
| `split4_input8` | train-only top-4 effect | top-8 outcome | испытываемое разделение |
| `oracle4_input8` | четыре истинных M | восемь истинных P∪M | недоступный в практике ориентир |

Дополнительные контроли на тех же train/eval: прямой arm mean по строкам `split4` и глобальные T-Learner HGB на всех 32 и на train-only input top-8. Для global моделей использовать те же HGB параметры, обучить на всём train отдельно по arms; не выбирать «лучший» по eval. Oracle нужен только для измерения остаточного запаса и не участвует в primary.

## Primary и решение

Для каждого seed вычислить CATE RMSE (PEHE) относительно истинной `tau_eval` и regret top-10% относительно oracle-top-10%. Обозначить `D=split4_input8`, `A=full_full`, `C=shared8_input8`, `T=global_T_input8`. **Статус перспективного метода** требует одновременно:

1. `mean[PEHE(A)−PEHE(D)] ≥ .010` и ≥7/8 положительных;
2. `mean[PEHE(C)−PEHE(D)] ≥ .005` и ≥6/8 положительных — добавочная роль отдельного retrieval;
3. `mean[PEHE(T)−PEHE(D)] ≥ .005` и ≥6/8 положительных — сильный классический контроль;
4. `mean[regret10(T)−regret10(D)] ≥ .005` и ≥6/8 положительных — польза решения.

Показать также D против `global_T_full`, direct local, oracle и `full_input8`, но не выбирать primary заново. Bootstrap средних разностей по восьми generated datasets: 10 000 draws, seed `20261022`; интервалы описательные и не эквивалентны внешней проверке. Непрохождение любого условия останавливает утверждение о готовом методе на этом маршруте; положительные вторичные эффекты назвать диагностическими. Ни Q̂ для непрерывного outcome, ни статистическую значимость на реальных популяциях здесь не заявлять.
