# M02 / E01 / v002 — фиксированная смесь feature-kNN и классических моделей

- **Статус:** complete_exploratory. Это разведочный пилот на уже просмотренных eval-разбиениях M01; версия v001 остаётся планом обучаемого веса на train/validation. Выбор `feature_knn_K512` после CS01/M01 не даёт независимого подтверждения.
- **Вопрос:** может ли простая смесь CausalPFN с S-, T- или X-Learner ранжировать получателей лучше **обоих** компонентов?
- **Источники:** неизменяемые снимки [CS01/E02/v001](../../../../../context_selection/hypotheses/CS01/results/E02/v001/20261017T170010_816255Z/README.md) и [M01/E02/v001](../../../M01/results/E02/v001/20261018T160846_900882Z/README.md). Их локальные предсказания на четырёх датасетах и split seeds `101/102/103` используются повторно; FM и классические модели не переобучаются.
- **Парность:** для каждого из 12 сочетаний «датасет × split» требуется идентичный упорядоченный `source_row`, `T`, `Y_benefit`, 4096 eval-строк, конечные scores и SHA-256 входных файлов. При ошибке остановить весь пилот, не подменять исходный запуск.
- **Метод:** для каждого eval-набора отдельно перевести score CausalPFN `feature_knn_K512` и score классической модели в percentile ranks `rankdata(method="average") / (n+1)`; затем `mix = 0.5·rank(FM) + 0.5·rank(classic)`. Три заранее заданные смеси — с S-, T- и X-Learner. Это batch targeting: нормализация использует scores всего eval-пакета без treatment/outcome labels. Вес `0.5` и список моделей не выбираются по Q̂ на eval. Смесь вероятностей или калибровка CATE не заявляются.
- **Основная метрика:** Q̂ (`normalized_qini_auc`, `sklift.metrics.qini_auc_score`). Для каждой пары показать `mix − FM` и `mix − classic` внутри split, затем средние и число положительных split по датасету. Описательный сигнал комплементарности: обе средние разности положительны и обе разности одновременно положительны хотя бы в 2 из 3 split. Это не тест статистической значимости и не правило выбора победителя из трёх моделей.
- **Дополнительно:** `normalized_auuc` и `uplift_10_pp` для всех компонентов и смесей. На каждом split 500 парных bootstrap выборок eval-строк с сохранением treatment arms; 95% percentile интервалы для двух Q̂-разностей каждой смеси. При bootstrap зафиксировать исходные score и percentile ranks, то есть интервалы условны на наблюдаемом eval-пакете, моделях и split.
- **Ограничения:** split пересекаются по исходным данным; на Criteo меняются и split, и исходная 100k выборка. CausalPFN, модели и идея смеси уже обсуждались после просмотра M01 eval. Выводы v002 могут только отобрать кандидата для нового подтверждающего эксперимента. Для выбора веса на train/validation и оценки на новых split потребуется новый FM-инференс; это отдельная будущая версия.
- **Команда:** из корня репозитория `.venv/bin/python -u tools/run_m02_e01_v002.py --check`, затем `.venv/bin/python -u tools/run_m02_e01_v002.py`. Первый режим только проверяет 12 пар входов и хеши; второй создаёт новый UTC run ID, локальные scores в `artifacts/local/m02_e01_results/` и компактный неизменяемый снимок в `results/E01/v002/<run-id>/` с протоколом, метриками, парными разностями, хешами, Git SHA и копией кода.
