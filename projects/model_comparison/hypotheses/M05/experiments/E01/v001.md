# M05 / E01 / v001 — парный тест бинарного и непрерывного outcome

- **Статус:** plan. Owner: команда M05. Зафиксировать протокол и SHA кода Git-коммитом до просмотра PEHE.
- **Мотив:** [CausalPFN](https://arxiv.org/html/2506.07918v2) обучен оценивать условные средние потенциальных исходов и тестировался на полусинтетическом CATE и маркетинговом uplift; [Nyberg et al.](https://proceedings.mlr.press/v157/nyberg21a.html) показывают важность дисбаланса класса в uplift. Наши ACIC/IHDP и RCT различаются одновременно многими свойствами. Этот тест изолирует тип наблюдаемого исхода, **не** утверждая, что он уже объясняет разницу между реальными задачами.
- **Данные:** восемь независимых generated seeds `2401–2408`; каждый содержит 4096 train и 512 eval строк, восемь `X_j ~ Uniform[-1,1]`, независимое `T ~ Bernoulli(0.5)`. Истинные функции `p0(x)=0.30+0.09 sin(pi*x0*x1)+0.05*x2`, `tau(x)=0.04+0.07 sin(pi*x3*x4)+0.035*x5`, `p1=p0+tau` (индексы с нуля). Проверить `0<p0,p1<1`. Для каждой строки и arm сохранить независимый `U~Uniform(0,1)`. Бинарный потенциальный исход `Y_t^B=1{U_t<p_t}`; непрерывный `Y_t^C=p_t+sqrt(p_t(1-p_t))*Phi^{-1}(1-U_t)` с clipping `U` только для численной конечности. Обе семьи имеют одинаковые условные средние `p_t`, дисперсии `p_t(1-p_t)` и CATE `tau`; в каждой наблюдать только `Y_T`. Сохранять исходные `X,T,U` и фактические исходы обеих семей. Никакие eval-outcome или истинные функции не подавать моделям.
- **Равный доступ:** StandardScaler обучать только на train; для каждого eval-query один общий feature-kNN контекст из `K=512` train-строк, по 256 из каждого treatment arm. Те же индексы и преобразованные X использовать для обеих семей. CausalPFN checkpoint `vdblm/causalpfn` revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, temperature 1, без обучения и калибровки на test. Сравнить с прямой разностью средних исходов на **том же** контексте, локальной `Ridge(alpha=10, fit_intercept=True)` по каждому arm на том же контексте и глобальным HistGB T-Learner (`learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, seed `42`) на тех же train-строках. HistGBRegressor использовать для обеих семей, чтобы не менять базовый алгоритм вместе с типом outcome; параметров по eval не подбирать.
- **Primary:** PEHE = RMSE оценки CATE относительно известной `tau` на 512 eval-строках. Для seed и типа `y` определить `A_y=[PEHE(local Ridge_y)−PEHE(FM_y)]/SD(tau_eval)`; основной парный interaction `I=A_continuous−A_binary`. Положительный `I` означает, что **относительное** преимущество FM над одинаковой локальной регрессией увеличилось с переходом к непрерывным наблюдениям при той же условной средней и дисперсии. Предзаданный описательный ориентир механизма: средний `I>0.1` и `I>0` минимум в 6/8 генераций. Если он не выполнен, эта версия объяснения не поддержана.
- **Дополнительные границы:** отдельно показать абсолютную PEHE всех четырёх методов в обоих режимах, `PEHE(T)−PEHE(FM)`, FM против прямого локального среднего и oracle regret@10% для ранжирования по истинному CATE. Даже если primary выполнен, сильное утверждение о пригодности FM требует его преимущества над **обоими** Ridge и T хотя бы в 6/8 непрерывных случаев и не худшего среднего oracle regret@10%; иначе остаётся только диагностический interaction. Не выбирать лучший baseline по eval и не заменять primary после расчёта.
- **Неопределённость:** показать восемь парных `I`, среднее, медиану, SD, число положительных; generated seed — единица повторения. Одна семья DGP и восемь реализаций не дают статистического доказательства переносимости. Для реальной статьи потребуются другая DGP-семья и независимый RCT; новые seeds этого же генератора не будут таким подтверждением.
- **Архив:** все X/T/U, исходы, истинные p и tau, контексты, полные score и статусы в исключённом `artifacts/local/m05_e01_results/`. Компактный неизменяемый результат с метриками, парными контрастами, хешами локальных файлов и Git/code SHA в `results/E01/v001/<run-id>/`. При сбое статус `incomplete`; запланированные seeds не подменять.

Из корня репозитория: `.venv/bin/python tools/run_m05_e01.py --check` проверяет DGP, checkpoint и условия доступа без FM-метрик; `.venv/bin/python tools/run_m05_e01.py --smoke` выполняет два FM-запроса; `.venv/bin/python -u tools/run_m05_e01.py all` считает все восемь пар; `.venv/bin/python tools/run_m05_e01.py --status` показывает прогресс.
