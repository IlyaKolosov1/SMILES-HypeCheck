# M06/E02/v001 — независимая проверка поправки к контексту

**Статус:** plan, exploratory mechanistic test. Owner: команда M06. Протокол и код должны попасть в Git до просмотра FM-метрик. [E01](../E01/v001.md) был ретроспективным и мотивирует именно этот один тест; его ACIC/IHDP/M05 score не используются для обучения или подбора параметров E02.

## Данные и фиксированные решения

Четыре новые генерации с seeds `2601–2604`. В каждой `4096` train и `512` eval строк; восемь независимых `X_j ~ Uniform[-1,1]`, `T ~ Bernoulli(0.5)`. Истинные функции:

`mu0(x)=0.8*x2+0.5*sin(pi*x3)`, `tau(x)=0.15+0.6*sin(pi*x0)+0.3*x1`, `mu1=mu0+tau` (индексы с нуля). Наблюдать только `Y_T=mu_T(X)+epsilon_T`, где независимые `epsilon_0,epsilon_1 ~ Normal(0,0.3²)`. Исходные X, T и шумы сохранять. Истинные `mu_t` и `tau` доступны **только** диагностике и метрикам; модели их не получают.

StandardScaler обучать на train. Для каждой eval-строки создать два treatment-balanced контекста одинакового размера `K=512`, по 256 строк на arm: (1) ближайшие по стандартизованным признакам train-строки в каждом arm; (2) случайные без повторения внутри arm для каждого запроса, RNG seed `seed+10000`. Внутри генерации X, T, Y, eval и бюджет одинаковы; меняются только индексы контекста. Предварительная проверка **без FM** на заданных seeds дала oracle-local RMSE около `0.30–0.31` для feature и `0.45–0.47` для random; это проверка силы манипуляции, а не результат FM.

CausalPFN checkpoint `vdblm/causalpfn`, revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, без дообучения и test-калибровки. Сравнить с прямой разностью средних наблюдаемых исходов **в тех же контекстах** и фиксированным глобальным HistGB T-Learner на тех же train-строках (`learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, seed `42`). Подбора по eval нет.

## Проверяемое предсказание

Основная метрика — PEHE по известному CATE. Для каждого seed вычислить `G_local=PEHE(local_random)−PEHE(local_feature)` и `G_FM=PEHE(FM_random)−PEHE(FM_feature)`. Primary interaction `I=(G_local−G_FM)/SD(tau_eval)`. Предсказание механизма: модельная поправка частично компенсирует плохую геометрию random-контекста, поэтому `I>0`. Заранее заданный **описательный** ориентир: среднее `I>0.1` и `I>0` в 4/4 генерациях. Сначала проверить, что oracle-local RMSE для random выше feature в 4/4; иначе манипуляция не удалась.

Дополнительно считать корреляцию `(FM−local)` с `(tau−oracle_local)` внутри seed и контекста, RMSE oracle-local, шумовую компоненту и oracle regret@10% (истинный CATE известен). Направление корреляции интересно, но не является независимым p-value. **Практический барьер:** FM-feature должен иметь меньший PEHE, чем local-feature и глобальный T, минимум в 3/4 генераций, а его средний oracle regret@10% не должен быть выше обоих. Если primary ориентир выполнен, но этот барьер нет, вывод касается только механизма, а не нового метода или лучшей uplift-политики.

Четыре генерации одного DGP — разведочная проверка. Показывать четыре парных значения, среднее, медиану и число положительных; обычный t-test по четырём случаям не делать. Не менять seeds, DGP, K, primary или порог после просмотра FM. При сбое пометить run `incomplete`; не заменять seed.
