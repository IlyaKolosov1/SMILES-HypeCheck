# M06/E14/v001 — перенос зависимости от K на опубликованный бинарный benchmark

**Статус до расчёта:** протокол зафиксирован до просмотра score CausalPFN на этом источнике. Данные — [Zhao (2022), Zenodo v1](https://zenodo.org/records/6342553), связанная [работа о feature selection](https://arxiv.org/abs/2005.03447). Публикация предшествует нашим M06-экспериментам. Это искусственно созданные бинарные uplift-задачи с известными вероятностями потенциальных исходов, **не внешний полевой RCT**. Файл не входит в Git.

## Вопрос и альтернативное объяснение

В M06/E06–E08 увеличение парного контекста K64→128 повышало относительную точность CausalPFN по сравнению с регрессионно скорректированным средним на тех же соседях. Проверяем перенос знака и размера эффекта на **ранее опубликованный бинарный генератор с 20 нерелевантными из 36 признаков**, который мы не конструировали по результатам FM. Альтернатива: прежний эффект специфичен для непрерывных исходов или искусственно выбранных функций; при бинарном Y, шумной геометрии и ограниченном числе событий FM не даёт дополнительной поправки к adjusted local.

## Данные и фиксированное разбиение

- Источник: `synthetic_uplift_data.csv`, DOI `10.5281/zenodo.6342553`; опубликованный MD5 `48101d5fa9fac9ea530b81375108afb6`, размер 785 863 095 байт. Сохранить исходный SHA-256 после загрузки. В файле ожидается 50 `trial_id` по 20 000 строк, treatment `control/treatment1` поровну; несовпадение останавливает запуск.
- Взять **trial 0–9**, без отбора по метрикам. В каждом trial из его 20 000 строк с `default_rng(27014 + trial_id)` выбрать первые 672 индекса перемешанной последовательности для train и следующие 512 для eval. Исходный порядок файла после фильтрации trial сохраняется. Разбиения trial не пересекаются. Не заменять trial при неудобном результате.
- Вход: все 36 `x1`–`x36`; идентификатор строки, trial, treatment, factual `conversion`, `control_conversion_prob`, `treatment1_conversion_prob` и `treatment1_true_effect` **не** входят в модель и поиск. Истинный eval CATE — разность двух опубликованных условных вероятностей, проверенная против `treatment1_true_effect`; используется только при оценке. Никаких oracle-подсказок о том, какие признаки информативны.
- `StandardScaler` обучается только на train каждого trial. `feature-kNN` отдельно внутри каждого treatment arm по всем 36 стандартизованным признакам. Один вложенный контекст K128 (64 на arm); K64 — первые 32 на arm. Проверить идентичность отдельному kNN-запросу, отсутствие повторов и непересечение train/eval. Никакого подбора metric/feature set.

## Методы и метрики

- CausalPFN: тот же локально закреплённый checkpoint/revision, CPU, `calibrate=False`, без дообучения. Для каждого eval-запроса пересчитать score при K64 и K128 на вложенных соседях.
- Контроль `direct_local`: разность средних наблюдаемых `conversion` по arms **того же** контекста. `adjusted_local`: разность средних `Y_i + m_t(x_query) − m_t(X_i)` по тем же соседям. Arm-wise `m_t` — 5-fold `HistGradientBoostingClassifier(learning_rate=0.05,max_iter=200,max_leaf_nodes=31,l2_regularization=1.0,random_state=42)` без настройки, обученный только на train. Для каждого донора и query берётся модель, исключившая fold донора. Глобальный T-контроль — среднее по пяти `m_1(x)−m_0(x)`; дополнительно константный train-ATE. Adjusted/global используют метки **всех 672 train-строк**, FM получает 64/128 меток на запрос; этот информационный бюджет показать явно.
- Для trial `D(K)=[PEHE(adjusted_local_K)−PEHE(FM_K)]/SD(true eval CATE)`; primary — `Δ_K=D(128)−D(64)` по десяти trial. Если SD нулевая, запуск пометить `incomplete`, не менять trial. Предзаданный **описательный ориентир переноса**: среднее `Δ_K>0.05` и минимум 8/10 положительных. Показать все десять пар, среднее, медиану и 5000 bootstrap-перевыборок trial для условного интервала. Это десять повторений **одного** внешнего генератора, не десять независимых кампаний.
- Вторично: абсолютные D64/D128, PEHE каждого метода, oracle regret@10% (верхние `ceil(0.1×512)` eval по предсказанному CATE, stable tie-break) и время методов. Практический ориентир для дальнейшей статьи требует при K128 меньшего среднего regret, чем **оба** adjusted local и global T, минимум в 7/10 trial для каждого сравнения. Он не заменяет primary. При выполнении только primary допустим узкий вывод о зависимости относительной точности от K, а не об улучшении таргетинга.

## Исполнение и ограничения

- До FM-инференса `--check` сверяет MD5/SHA файла, схему, полные размеры и arms, конечность, бинарность, правильность истинного CATE, разбиения, вложенные контексты и наличие checkpoint. `--check` не обучает и не читает значения score. `--status` только читает состояние.
- До `all` протокол и runner должны быть в Git. Ожидается `10 × 2 × 512 = 10 240` FM-query и 100 classifier fits. Оценка CPU 8–25 минут после загрузки на основе E08, но 36 входов и бинарный исход могут её изменить; RAM ориентировочно до 3 ГБ, локальный диск около 1 ГБ с исходным CSV. Прогрессбар показывает этап, trial, fits/query, elapsed/ETA; нет TTY — редкие строки и `status.json`. Прерывание даёт `incomplete`; resume не предусмотрен.
- Команды из корня репозитория: `.venv/bin/python -u tools/download_zhao_uplift.py`, `.venv/bin/python -u tools/run_m06_e14.py --check`, `.venv/bin/python -u tools/run_m06_e14.py all`, `.venv/bin/python tools/run_m06_e14.py --status`. Большой CSV, контексты и score — в `artifacts/local/`; компактный неизменяемый снимок — `results/E14/v001/<run-id>/` с исходным протоколом, Git SHA, SHA кода/checkpoint/источника и парными результатами.
- Источник специально создан для исследования feature selection: 20 лишних признаков могут влиять на оба метода и на поиск. Без отдельного train-only выбора признаков отрицательный результат не исключает пользы FM в другой геометрии. Положительный результат не подтверждает policy-ценность на реальных пользователях. Известный CATE позволяет проверить механизм, но не устраняет границу переноса с генератора на практику.
