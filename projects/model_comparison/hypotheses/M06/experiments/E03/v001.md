# M06/E03/v001 — даёт ли FM пользу для таргетинга в полевом RCT?

**Статус:** plan, одна внешняя разведочная проверка. Этот протокол и код закрепить в Git **до** просмотра каких-либо модельных score/метрик на Michigan Social Pressure. В [M06/E02](../E02/v001.md) FM исправляла ошибку локального контекста по PEHE на одной синтетической DGP, но проиграла глобальному T-Learner по policy regret. [Künzel et al. (2019)](https://www.pnas.org/doi/full/10.1073/pnas.1804597116) нашли гетерогенность именно для письма `Neighbors` в исходном RCT и мотивируют сильный X-Learner baseline. Это проверка внешней границы, а не попытка воспроизвести их числа на другой обработанной выборке.

## Данные и деление

Использовать только обработанный `socialpresswgeooneperhh_NEIGH.csv` из [Stanford GSB ExperimentData](https://github.com/gsbDBI/ExperimentData/tree/master/Social/ProcessedData), SHA-256 `89ed926036d386e21815e2d5319bf1ee1be764b1d2f3c2757b4ead73bd0ffe9c`. 119 999 строк, ровно один избиратель на `hh_id`, 10 000 блоков `cluster`, 2 `Neighbors` в каждом блоке и 10 control (в одном блоке 9 control). `T=treatment_dum`, `Y=outcome_voted`, оба бинарные; estimand — эффект **назначения письма**, так как фактическое чтение неизвестно. Признаки только `sex`, `yob`, `g2000`, `g2002`, `p2000`, `p2002`, `p2004`, `hh_size`. `g2004` константен; `votedav`, география, `randn`, IDs, treatment/outcome не входят в X. Описание аудита: [внешние данные](../../../../../../docs/EXTERNAL_DATA_AUDIT.md).

Перемешать отсортированные уникальные `cluster` с `default_rng(2701)` и назначить первые 5000 блоков train, остальные eval. Все строки одного блока остаются вместе. По `cluster` и `hh_id` пересечения запрещены. StandardScaler обучить только на train; обе модели и поиск соседей получают одинаковые восемь признаков. Исходные строки и контрольные суммы сохранить локально. Без подбора признаков, seeds, K или бюджетов после просмотра eval-метрик.

## Методы при общем train bank

- `FM_feature`: замороженный CausalPFN `vdblm/causalpfn`, revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, без калибровки; для каждого eval-запроса по 256 ближайших train-строк **отдельно** в control и treatment, после train-only стандартизации; `K=512`.
- `local_feature`: разность средних наблюдаемых `Y` в **тех же 512 строках**. Это контроль добавочной ценности FM при одинаковом retrieval.
- `FM_random` и `local_random`: по 256 случайных train-строк в каждом arm на запрос, без повторов, seed `2702`, тот же бюджет. Одна реализация random является только ориентиром чувствительности.
- `X_HistGB`: X-Learner с HistGradientBoostingClassifier для исходов и HistGradientBoostingRegressor для псевдоэффектов; `learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, seed `42`. Вес моделей эффекта по известной доле treatment в train, как в M01. Вторичный `T_HistGB` использует те же две модели исхода. Эти фиксированные варианты **не** воспроизводят X-RF из PNAS.

## Основной вопрос и оценка

Операционный бюджет — письма верхним **40%** eval-домохозяйств по score каждого метода (ровно `ceil(0.4*n_eval)`; tie разбирать стабильным порядком `hh_id`). Это выбранный до score бюджет: группа с тремя из пяти прежних голосований составляет 41,9% аудированной выборки. Primary contrast — эффект назначения письма среди выбранных `FM_feature` **минус** эффект среди выбранных `X_HistGB`, в процентных пунктах. Основной estimator — общий для всех методов AIPW pseudo-effect с известной propensity `2 / размер блока` (то есть `1/6` почти всюду, `2/11` в одном блоке) и двумя outcome-моделями, обученными только на train. Считаем среднее pseudo-effect по выбранным 40%. Парную разность оценивать по той же eval-выборке, фиксируя обученные модели и членство в политиках; 1000 bootstrap-перевыборок **блоков** `cluster`, seed `2703`, percentile 95% CI. Дополнительно дать IPW без nuisance как анализ чувствительности.

Вторичные контрасты: `FM_feature − local_feature`, `FM_feature − FM_random`, `FM_feature − T_HistGB`; Q̂ (`normalized_qini_auc`) и AIPW value на бюджетах 20% и 60% только описательно. Показать долю перекрытия выбранных домохозяйств: если политики почти совпали, малую разность интерпретировать с учётом этого. Не выбирать лучший бюджет или baseline по eval.

**Заранее заданный практический ориентир:** primary разность строго положительна, её блоковый 95% CI исключает 0, и `FM_feature − local_feature` тоже положительна. Если этот ориентир не выполнен, E03 не подтверждает пригодность FM для таргетинга и не оправдывает поиск новых seeds/бюджетов на том же RCT. Даже при успехе это одно поле, одна обработанная версия и один treatment; для статьи потребуется ещё независимое подтверждение и сравнение с другими сильными causal estimators.

## Выполнение и ограничения

Перед инференсом проверить SHA файла, схему, размеры блоков, группу назначения, отсутствие пропусков, непересечение train/eval и локальный checkpoint. Сохранить предсказания, индексы контекста и статусы в исключённый из Git `artifacts/local/m06_e03_results/<run-id>/`, компактные протокол/метрики/парные разности/хеши/SHA кода и исходного Git commit — в `results/E03/v001/<run-id>/`. Не пересоздавать split при сбое. `--check` без обучения и FM; `--smoke` проверяет два FM-запроса без eval-метрик; `all` выполняет один фиксированный расчёт; `--status` показывает прогресс.

В RCT treatment назначался блоками по домохозяйствам. Блоковый bootstrap условен на обученном score и не охватывает новую кампанию, другую популяцию или возможные spillovers между соседями. Оценка относится к intention-to-treat; нельзя подменять её эффектом прочтения письма. Протокол зафиксирован до просмотра score моделей на этом файле; опубликованные результаты X-Learner известны заранее и не являются нашим независимым открытием.
