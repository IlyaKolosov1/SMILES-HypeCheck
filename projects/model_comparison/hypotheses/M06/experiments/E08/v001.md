# M06/E08/v001 — новая семья задач для проверки относительного эффекта K

**Статус:** протокол до генерации score и просмотра outcome-метрик. Основание — [кандидатная гипотеза](../../../../../../docs/roadmap/SHORT_PAPER_HYPOTHESIS.md) после E06/E07: рост K улучшал FM относительно скорректированного local на уже просмотренных ACIC/IHDP. E08 — заранее заданная **новая генерация** с двумя различными механизмами, не новые seeds прежних ACIC/IHDP/M06/E02. Это независимые draws из закреплённого кода, но семейства сконструированы после предыдущих результатов; не выдавать их за внешний реальный источник.

## Полный дизайн до вычислений

- Три семейства: `smooth_gate` (гладкие нелинейные взаимодействия, 8 seeds `3101–3108`), `threshold_gate` (пороговые взаимодействия, те же 8 seeds), `constant_control` (постоянный CATE, seeds `3191–3192`). Показать **все** случаи независимо от направления эффекта; primary только первые две семьи.
- Для каждого seed: 672 независимых train и 512 eval covariates, 12 признаков (8 непрерывных, 4 бинарных), корреляции между парами непрерывных признаков. У двух heterogeneous семейств при одинаковом seed совпадают covariates, treatment и независимые шумы, но различаются заданные функции потенциальных исходов. Eval не участвует в fit, выборе соседей по другим query или настройке метода.
- Treatment на train и eval: Bernoulli с `propensity=clip(sigmoid(0.4*x0−0.3*x2+0.2*(x8−0.5)+0.2*x3*x4),0.2,0.8)`. Все train arm counts проверить до расчёта; минимум 64/arm для K128. Никаких замен seed при неудобном балансе или исходе.
- Потенциальные средние (индексы с нуля): `smooth_gate`: `mu0=0.7*tanh(x0+x1)+0.4*x2+0.2*x8`; `tau=0.2+0.7*exp(−(0.8*x0−x1)^2)+0.35*tanh(x3+x4)−0.35*x9`. `threshold_gate`: `mu0=0.5*1[x0>0]+0.35*1[x2+x3>0]+0.15*x4`; `tau=0.6*1[x0>0,x1<0]−0.45*1[x2>0]+0.25*x9+0.15`. `constant_control`: `mu0=0.5*tanh(x0)+0.3*x2`, `tau=0.25`. `mu1=mu0+tau` везде. К каждому потенциальному outcome добавить **независимый** `Normal(0,0.5)` шум, factual outcome определяется только назначенным treatment. Истинный eval CATE = `tau(x)` и используется лишь для оценки.
- `StandardScaler` fit только на train; feature-kNN отдельно внутри treatment arms. Один K128 контекст (64/arm) строить по расстоянию и брать его первые 32/arm для вложенного K64; проверить совпадение с отдельным kNN запросом. Те же соседи для FM, direct local и adjusted local. CausalPFN: закреплённая ревизия/хеш checkpoint прежних M06, CPU, `calibrate=False`, без fine-tuning.
- Для каждого случая один раз обучить 5-fold arm-wise `HistGradientBoostingRegressor(learning_rate=.05,max_iter=200,max_leaf_nodes=31,l2_regularization=1,random_state=42)` как в E04–E07. Обе поправки `m_t(x)` и `m_t(X_i)` в слагаемом вычисляются моделью без fold донора. Сохранить adjusted K64/K128, FM K64/K128, прямое local, global cross-fit и train-ATE. Гиперпараметры не подбирать по eval.

## Primary, вторичные метрики и решение

Для каждого heterogeneous случая `D(K)=[PEHE(adjusted_K)−PEHE(FM_K)]/SD(true eval CATE)`. Primary **отдельно в каждой новой семье**: `Δ_K=D(128)−D(64)`. Предзаданный описательный ориентир переноса: `mean Δ_K>0.05` и минимум `6/8` положительных **в обеих** семьях. Обе семьи равноправны; не объединять их для обхода отрицательного результата. `constant_control` исключён из нормировки и primary, оценивать его сырой PEHE/политикой как negative control. Сохранить 8 разностей каждой семьи, среднее, медиану, число положительных и 5000 bootstrap-перевыборок **независимых seed-cases** внутри семьи для интервала среднего. Это неопределённость генератора при фиксированном DGP, а не перенос на реальную кампанию.

Вторично: абсолютный D128 и D64; normalized/raw PEHE каждого метода; oracle regret@10% при `ceil(0.1*512)=52` eval-строк и stable sort; время FM-инференса, nuisance-fit, память и объём контекста. Не выбирать лучший K по eval и не превращать выигрыш PEHE в утверждение о политике. Если primary не проходит хотя бы в одном heterogeneous семействе, широкий механизм «больше K повышает относительную пользу FM» **не подтверждён** этой новой проверкой; сообщить отрицательную семью полностью. Если проходит, для статьи всё равно нужен проверенный практический эффект и сравнение compute/label budget.

## Исполнение, контроль и ресурсы

До запуска `--check` воспроизводит 18 исходных случаев и проверяет arm counts, конечность, разные train/eval, свойства CATE, вложенность контекстов и локальный checkpoint; модель не обучается, FM не вызывается, eval-метрики не считаются. Протокол и код фиксируются в Git **до** `all`. Всего `18×2×512=18 432` FM query и 180 HistGB fits. По замеру E06 (~38k query за 7 минут) ожидание 4–8 минут CPU, RAM <2 GB, локальный диск <100 MB; runner покажет фактические elapsed/ETA. Большие `base.npz`, контексты и score — только `artifacts/local/m06_e08_results/<run-id>/`. Компактный неизменяемый снимок — `results/E08/v001/<run-id>/` с протоколом, Git SHA/кодом, checkpoint SHA, хешами локальных файлов, метриками и парными разностями.

TTY-прогрессбар — одна перерисовываемая строка по query с текущей семьёй/seed/K, стадией, fits, elapsed/ETA; без TTY — редкие статусы. `--status` лишь читает статус. При сбое папка `incomplete`; resume нет, новая попытка получает новый run-id. Из корня репозитория: `.venv/bin/python tools/run_m06_e08.py --check`, `.venv/bin/python -u tools/run_m06_e08.py all`, `.venv/bin/python tools/run_m06_e08.py --status`. Анализ только после `RUN COMPLETE` и проверки снимка.
