# M06/E04/v001 — выдерживает ли FM сравнение с коррекцией двух поверхностей?

**Статус:** подготовлен к исполнению, ретроспективная диагностика уже просмотренного M06/E02. Owner: команда M06. Этот протокол и `tools/run_m06_e04.py` должны быть закреплены в Git до расчёта новых score. [Roadmap](../../../../../../docs/roadmap/README.md) объясняет место проверки в исследовании.

## Вопрос и источник

В [E02/v001](../E02/v001.md) CausalPFN с feature-контекстом получила меньшую PEHE, чем прямое среднее по тем же 512 соседям, но преимущество политики над глобальным T-Learner не появилось. Проверить, остаётся ли преимущество по PEHE после известной классической [регрессионной коррекции matching](https://economics.mit.edu/sites/default/files/publications/Bias-Corrected%20Matching%20Estimators%20for.pdf) **обоих** потенциальных исходов. Новизну самой коррекции не заявлять.

Переиспользовать неизменённый [снимок E02](../../results/E02/v001/20261020T064050_536130Z/README.md), включая четыре `base.npz`, feature/random контексты, score CausalPFN, прямого local и глобального T. Источник локально — `artifacts/local/m06_e02_results/20261020T064050_536130Z/`; 54 входных SHA записаны в `local_files.csv` снимка. Seeds `2601–2604`, по 4096 train / 512 eval, `K=512` (256 каждого arm), прежние outcome и контексты. Истинные `tau_eval` используются только для оценки; `mu0/mu1` не входят в модели. Нового FM-инференса нет.

## Фиксированный метод

Для каждого seed и treatment arm отдельно выполнить `KFold(n_splits=5, shuffle=True, random_state=42+arm)`. На четырёх folds обучать `HistGradientBoostingRegressor` с `learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, `random_state=42`, `max_bins`/`min_samples_leaf` по умолчанию. Признаки стандартизировать одним `StandardScaler`, обученным только на исходном train, как в E02. Выбора гиперпараметров нет; конфигурация совпадает с глобальным T-контролем E02.

Для каждого train-донора `i` его residual и прогноз для eval-запроса `x` считать **той же arm-моделью**, обученной без fold донора: `Y_i + m_t^(-fold(i))(x) − m_t^(-fold(i))(X_i)`. Взять среднее по сохранённым соседям `C_t(x)`; затем вычесть arm 0 из arm 1. Это `adjusted_feature` и `adjusted_random`. Для контроля сохранить глобальный cross-fit ensemble `mean_fold m_1(x) − mean_fold m_0(x)` и постоянную разность factual train-средних. Сравнить с сохранёнными `fm_feature/random`, `local_feature/random`, `global_t`. Одинаковые соседские индексы для FM/local/adjusted; никакой замены K, seed или eval-строк.

Классическая вспомогательная регрессия использует outcome **всего train bank**, а FM на запрос видит labels только своих 512 соседей. Это сравнение практического результата при общем доступном train, **не** изоляция пользы претрейнинга при равном числе labels на входе. Fixed `Ridge(alpha=10)` из M01/E14 уже сравнивалась на ACIC/IHDP и не является этим baseline.

## Метрики и решение

Primary для каждого seed: `D = [PEHE(adjusted_feature) − PEHE(fm_feature)] / SD(tau_eval)`. Положительное `D` означает преимущество FM. Показать четыре `D`, среднее, медиану и число положительных. **Описательный порог для продолжения FM-механизма:** среднее `D > 0.05` и минимум 3/4 `D > 0`. При меньшем выигрыше на этой DGP не строить новый FM-метод на утверждении, что простой local был принципиально слабым; искать другое обоснование. Порог не является p-value или доказательством переносимости, особенно с уже просмотренным E02.

Вторичные сравнения: PEHE и oracle regret@10% всех методов, те же методы при random-контексте, эффект feature−random у adjusted и FM, выигрыш adjusted над direct local, выигрыш/проигрыш против сохранённого глобального T и train-ATE. Regret использовать прежнее `ceil(0.1*512)`, сортировка stable по score, без изменения бюджета. Дать 1000 парных bootstrap-перевыборок eval-строк внутри каждого seed, RNG `2804`, с фиксированным знаменателем `SD(tau_eval)` для условного интервала среднего `D`. Не делать t-test по четырём seeds одного DGP. Если adjusted сравняется с FM по PEHE, проверить также regret; равенство point estimates или интервал через ноль **не доказывают** эквивалентность.

E02 outcome и FM-результаты уже были просмотрены, метод выбран после них. Даже положительный результат E04 будет диагностикой, а не новым независимым подтверждением. При неясном исходе не менять параметр/seed на том же eval ради желаемого знака. Следующий внешний policy-тест возможен только после отдельного нового метода и source.

## Проверка, ресурсы и сохранение

Перед обучением сверить все 54 SHA источника, завершённость четырёх случаев, размеры, treatment-balanced контексты, прямые local-score и сохранённую метрику E02. Несовпадение останавливает весь запуск. Один полный расчёт: **40 небольших HistGB fits** (4 seed × 2 arms × 5 folds), CPU, один поток BLAS/OMP; оценка 2–15 минут, менее 1 ГБ RAM и менее 20 МБ новых полных score. Это расчётная оценка без замера на этой машине; runner показывает elapsed/ETA.

Прогрессбар в TTY показывает выполненные folds/40, stage, seed, elapsed и ETA; при перенаправлении печатается редкое статусное сообщение. `status.json` и `--status` показывают стадию и число готовых fits. `--check` только проверяет источники. При ошибке результат остаётся `incomplete`; resume не предусмотрен, следующая попытка получает новый run-id. Полные score/статусы: `artifacts/local/m06_e04_results/<run-id>/`; после завершения компактный неизменяемый снимок: `results/E04/v001/<run-id>/` с метриками, разностями, протоколом, SHA источников/кода и Git commit.

Из корня репозитория: `.venv/bin/python tools/run_m06_e04.py --check` проверяет входы без обучения; `.venv/bin/python -u tools/run_m06_e04.py all` выполняет расчёт; `.venv/bin/python tools/run_m06_e04.py --status` показывает текущую стадию. Вывод анализировать после полного `RUN COMPLETE` и проверки снимка.
