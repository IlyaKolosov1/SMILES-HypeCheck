# M01 / E09 / v002 — интервалы для uplift@10% в сохранённом разложении контекста

- **Статус:** post-hoc повторный анализ уже просмотренных M01/E09/v001 результатов; не preregistered и не подтверждающий. Точечные `uplift@10%` по четырём датасетам и трём split были просмотрены до составления этой версии. Цель — понять, заслуживает ли наблюдаемый сигнал retrieval отдельной независимой проверки.
- **Вопрос:** насколько неопределённы уже сохранённые разности `uplift@10%` между feature-контекстом и средним по трём random-query контекстам у CausalPFN и direct-local? Никакого нового инференса, выбора контекста или изменения исходов не производится.
- **Источник:** неизменяемый M01/E09/v001 snapshot `20261019T170444_744777Z` и соответствующие 12 локальных `scores_<split>_<dataset>.csv`. До расчёта сверить manifest и SHA compact-файлов, исходных score-файлов и кода v001; проверить 4 096 уникальных eval `source_row` на каждом dataset × split, treatment/outcome и все восемь score-колонок.
- **Метрика и контрасты:** сохранить исходное определение v001 `uplift_10_pp`: разность observed outcome rate treated−control внутри top 10% строк по score; ties повторить по `source_row` и тому же SplitMix64 salt. В каждом bootstrap draw сначала вычислить uplift для каждого метода, затем усреднить **метрики** трёх random-context seeds. Основные описательные разности: `local_feature − local_random_mean` и `FM_feature − FM_random_mean`; `FM_context_gain − local_context_gain` и `FM_feature − local_feature` остаются диагностическими.
- **Интервалы:** 300 парных bootstrap draw eval-строк с возвращением отдельно внутри treatment arms, RNG seed `20261029 + split_seed + dataset_index × 10`. В одном draw одни resampled строки применяются ко всем восьми score; для каждой политики top 10% заново выбирается на bootstrap-выборке. Percentile 95% intervals условны на фиксированных исходных score, моделях, train и eval. Невалидные draw сохранять в счётчике; не подбирать seed или q.
- **Сводка:** для каждого dataset показать точечную разность и условный интервал отдельно по каждому из трёх split, затем равновесное среднее трёх точечных разностей и число положительных split. Не усреднять bootstrap draws по split и не трактовать splits как независимые повторения: они используют перекрывающиеся исходные данные. Коррекция множественности не выполняется; вывод только поисковый.
- **Ограничения:** гипотеза выбрана после просмотра E09 и прежних Criteo/Hillstrom результатов; bootstrap не учитывает неопределённость обучения или выбора split. Контрасты не являются новым независимым подтверждением. Q̂ v001 не пересчитывать и не менять; PEHE не использовать.
- **Хранение и прогресс:** никаких per-row scores в Git; новый неизменяемый компактный snapshot `results/E09/v002/<run-id>/` содержит протокол, delta/interval таблицы, bootstrap draws, source hashes и SHA кода. Скрипт выводит компактный progress bar по каждому dataset × split и поддерживает `--check`, `--status`, `--help`.

Запуск из корня: `.venv/bin/python -u tools/reanalyze_m01_e09_v002.py --check`, затем `.venv/bin/python -u tools/reanalyze_m01_e09_v002.py all`. Это вычисление только на сохранённых score и labels; FM не запускается.
