# M01 / E06 / v001 — CausalPFN против X-Learner и локального среднего на новых Criteo-когортах

- **Статус:** plan. Протокол выбран после CS01/E03 и M01/E04, до чтения `visit` новых когорт `404–406`. Criteo выбран по предыдущим положительным результатам: это условная проверка внутри одного источника, а не независимый тест выбора датасета.
- **Вопрос:** сохраняется ли добавочная ценность CausalPFN с treatment-balanced feature-контекстом одновременно против фиксированного X-Learner и прямого среднего uplift по тем же соседям?
- **Данные:** тот же очищенный `Criteo-ITE-v2.1`, SHA `features.parquet`, `outcomes.parquet` и `cleaning_metadata.json` сверить с CS01/E03; `T` и benefit outcome `visit`; десять `f*` признаков. Использовать исходную позицию `source_row` как ID. До выбора новых строк восстановить старые 100k-выборки seeds `42,301–303` и последовательные выборки `401–403`; сверить их с сохранёнными ID и исключить **полностью**. Из остальных строк последовательно без замены выбрать три новые выборки по 100 000 с seeds `404,405,406`. Не просматривать outcome до фиксации выборок и протокола.
- **Разбиения:** `(sample seed, split seed)=(404,114),(405,115),(406,116)`. Для каждого sample один group-safe split по одинаковым векторам признаков, `51 200` train и `16 384` eval. Train/eval и три когорты не пересекаются по source rows. Все модели используют ровно одинаковые ID, `T`, `visit`; преобразования обучаются только на train. При пустой ячейке `T × visit` сохранить `incomplete`, seed не менять.
- **FM:** закреплённый `vdblm/causalpfn` revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, `calibrate=False`, `K=512`, по 256 train-строк каждого treatment arm, query-dependent `feature_knn`. Никакой настройки по eval. Для каждого eval сохранить исходные `source_row` контекста и предсказание.
- **Baselines:** прямое среднее train-`visit` 256 treated минус среднее 256 control по тому же контексту; X-Learner на тех же 51 200 строках с `HistGradientBoostingClassifier` для исходов и `HistGradientBoostingRegressor` для pseudo-outcomes, `learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1.0`, `random_state=42`. Конфигурация повторяет CS01/E03, подбора нет.
- **Primary и критерий:** два заранее заданных парных Q̂ (`normalized_qini_auc`) контраста: `FM feature − X-Learner` и `FM feature − direct local`. Совместный **описательный** ориентир выполнен, только если средняя разность по трём новым когортам положительна и 3/3 когорт положительны **для обоих** контрастов. Ни один comparator не выбирается по eval. Отдельно показать величины и число положительных когорт; выполнение ориентира не означает статистическую значимость за пределами этого Criteo-источника.
- **Secondary:** Q̂ всех моделей, normalized AUUC и uplift@10% (верхний дециль с фиксированным стабильным разрешением ties), treatment/outcome counts, время, согласованность эффектов между когортами. Для двух Q̂-контрастов и uplift@10% по 500 парных stratified bootstrap-повторов eval-строк внутри каждой когорты; эти интервалы условны на обученных моделях и не учитывают выбор Criteo по прошлым результатам. Не превращать вторичные метрики в новый primary после просмотра.
- **Хранение:** полные предсказания, context IDs и промежуточные данные только в `artifacts/local/m01_e06_results/`; отдельные локальные папки по когортам со статусом `incomplete` при сбое; после трёх завершений — один компактный неизменяемый снимок `results/E06/v001/<run-id>/` с SHA входов/выходов, Git SHA, SHA кода, парными разностями, интервалами и кратким ограниченным выводом. Старые снимки не менять.

До полного запуска выполнить `--help`, `--check`, `--smoke`, проверить валидатор и зафиксировать код/протокол Git-коммитом. Затем `.venv/bin/python -u tools/run_m01_e06.py all` запускает когорты последовательно с однострочным прогрессом; `.venv/bin/python tools/run_m01_e06.py --status` показывает стадию. После выполнения независимо пересчитать Q̂, интервалы, парность и SHA, затем упаковать снимок. Примерное CPU-время — 1–2 часа, зависит от чтения parquet и скорости инференса.
