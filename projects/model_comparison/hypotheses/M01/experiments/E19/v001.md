# M01 / E19 / v001 — ресурсы train и контекста для реального targeting

**Статус:** протокол до FM-инференса и расчёта E19. Это первый исполняемый
вопрос [обзора после E18](../../../../../../docs/roadmap/OPEN_QUESTIONS_AFTER_E18.md).
Данные всех четырёх источников и исходы прежних экспериментов уже изучались:
новые разбиения служат development-проверкой внутри источников, а не
независимым подтверждением для статьи.

## Вопрос и заранее заданные сравнения

Меняется ли практическая разность CausalPFN с feature-kNN и фиксированного
X-Learner при независимом изменении числа доступных train-строк `N` и размера
контекста `K`? Факторный дизайн: `N={8192,51200}` × `K={512,2048}` на одних
eval-строках каждого источника. Primary: разность `uplift@10%` в процентных
пунктах `FM_feature(N,K) − X_learner(N)` для каждой ячейки, а также её
изменение по `N` и по `K` внутри источника. Q̂ (`normalized_qini_auc`)
обязательно показывать для каждой ячейки и модели. Все восемь факторных
сравнений и отрицательные разности показывать полностью; не выбирать
«удачный» источник или ячейку после расчёта. Описывать форму кривой и
стоимость, не объявлять значимость по четырём зависимым источникам.

## Данные, разбиения и модели

- Hillstrom `visit` — 12 800 eval; RetailHero `Y` — 140 000;
  LZD `Y` — 120 000; Criteo v2.1 `visit` — 100 000. Признаки и обработка
  соответствуют `multi_dataset_context.py`; хеши локальных исходных parquet
  записать. Criteo сначала равномерно выбрать 250 000 source-строк seed
  `20261031`. Строки и outcome из уже просмотренных источников не выдавать
  за новый RCT. Не включать Orange до уточнения его treatment semantics.
- Outer split seed `20261032`; для LZD/Criteo применять `GroupShuffleSplit`
  по хешу полного исходного вектора признаков (test fraction 0,68/0,5),
  для Hillstrom/RetailHero стратифицированное T×Y деление с указанным
  размером eval. При большем eval pool выбрать ровно требуемое число seed
  `20261035`. Из train pool выбрать 51 200 строк seed `20261033`, затем
  вложенные 8192 строк seed `20261034`, оба раза со стратификацией T×Y.
  Проверить уникальность source ID, непересечение train/eval ID и групп;
  не перегенерировать split после просмотра результатов.
- Для каждого N заново учить train-only preprocessing; feature-kNN берёт
  `K/2` ближайших control и `K/2` treated, одинаковые donor IDs для
  CausalPFN и прямого локального среднего. Веса CausalPFN:
  `vdblm/causalpfn`, revision
  `83aad07da1cb077cfda4236878a1b07dc9f72a54`, SHA фиксировать в
  запуске. Global S/T/X — фиксированный `HistGradientBoosting` из
  M01/E02: `learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`,
  `l2_regularization=1`, `random_state=42`; X заранее выбран как primary
  классический контроль. Он использует тот же N, не K.
- Доля выбираемых равна 10%; ties разрешать детерминированным hash
  `source_row`, как в M01/E08. `uplift@10%` = 100 × разность долей успеха
  treated/control среди выбранных. Условные 95% интервалы: 500 общих
  стратифицированных по arm bootstrap-выборок eval-строк с фиксированными
  score и top-10% masks; пересчитывать оба сравниваемых значения на одних
  индексах. Q̂ строится `sklift.metrics.qini_auc_score`.

## Ресурс и порядок

`--check` сверяет исходные файлы, split, T×Y клетки и вместимость K без
обучения. `--benchmark` проверяет CausalPFN на восьми запросах для двух K
и оценивает полную длительность; его score не использовать в анализе.
Проверка T×Y до FM-инференса дала оптимистичную iid-полуширину 95% интервала
для **случайного** top-10%: около `3,85/1,61/0,66/1,07` п.п. соответственно.
Это не мощность фактической пары методов; Hillstrom способен различить лишь
крупную разность. Даже для остальных источников узкий прирост около `+1` п.п.
может остаться неопределённым. Дизайн отвечает также на величину и форму
эффекта при разных ресурсах, независимо от знака.
Если полное время более четырёх часов, расчёт запускает участник. Runner
показывает этап, прогрессбар, ETA и status; после сбоя возобновляет те же
строки и тот же code SHA. Большие predictions и donor positions сохраняются
в `artifacts/local/`, компактный неизменяемый снимок содержит метрики,
разности, протокол, SHA исходных и локальных файлов и ограничения.

Для следующего [вопроса о другом backbone](../../../../../../docs/roadmap/OPEN_QUESTIONS_AFTER_E18.md)
понадобится **отдельный протокол** с matched feature/random donor IDs и
закреплённой версией TabPFN. Пакет сейчас не установлен, а скорость на
наших данных ещё неизвестна. После E19 научное решение о mix и выборе
selector принимается по результату, как требуют [правила экспериментов](../../../../../../docs/EXPERIMENTS.md).
