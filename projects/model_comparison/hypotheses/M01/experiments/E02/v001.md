# M01 / E02 / v001 — CausalPFN против фиксированных S/T/X-Learner

- **Owner:** исследовательская команда M01. **Статус:** complete_exploratory; технический результат упакован, научный разбор и проверка вторым участником ожидаются.
- **Вопрос:** как два варианта CausalPFN соотносятся с классическими meta-learners на тех же train/eval строках? Это разведочное сравнение после CS01/E02; выбор вариантов FM сделан с учётом уже увиденных результатов CS01.
- **Источник:** завершённый [CS01/E02/v001](../../../../../context_selection/hypotheses/CS01/experiments/E02/v001.md), [снимок и хеши](../../../../../context_selection/hypotheses/CS01/results/E02/v001/20261017T170010_816255Z/README.md). Его предсказания CausalPFN используются как есть; нового инференса FM нет.
- **Данные:** Hillstrom `visit`, Retailhero-uplift `Y`, LZD `Y`, Criteo-ITE-v2.1 `visit`; treatment `T`. Orange не включён по ранее зафиксированному правилу. Для Criteo сохраняются три разные 100k source sample seeds `301/302/303`, соответствующие split seeds `101/102/103`.
- **Парность:** для каждого из 12 сочетаний «датасет × split» брать сохранённые `train_rows.csv` (51 200 строк), `eval_rows.csv` (4096 строк) и `predictions.csv` из CS01/E02. Первичные парные сравнения строятся только при идентичном порядке `source_row`, treatment и outcome. В LZD/Criteo дополнительно проверяется отсутствие пересечения групп одинаковых признаков между train/eval.
- **Признаки и preprocessing:** тот же список feature columns, что в `fold_config.json` CS01. Числовые признаки: train-fitted median imputation + standard scaling; категориальные: train-fitted most-frequent imputation + one-hot с обработкой новых категорий. Во всех 12 исходных fold не использовался SVD. Eval не участвует в обучении или выборе параметров.
- **Классические модели:** `HistGradientBoostingClassifier` в outcome-моделях S-, T- и X-Learner; `HistGradientBoostingRegressor` для двух моделей псевдоэффекта X-Learner. Общие фиксированные параметры из старого пилота: `learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1.0`, `random_state=42`. Подбора параметров нет. X-Learner использует псевдоэффекты от модели противоположного treatment arm и вес `p(T=1)` из train: `p·tau_control + (1−p)·tau_treated`.
- **FM:** два равноправных варианта: `feature_knn_K512` и `random_query_mean_K512`. Последний — среднее **трёх отдельно посчитанных значений метрики** для `random_query_s201/s202/s203_K512`, не ансамбль предсказаний и не три независимых разбиения.
- **Primary метрика и семья сравнений:** Q̂, колонка `normalized_qini_auc`, функция `sklift.metrics.qini_auc_score`. Шесть заранее заданных разностей `FM − classic` на каждом датасете и split: два варианта FM × S/T/X-Learner. Не выбирать лучшую классическую модель по eval. Дополнительно вывести AUUC (`normalized_auuc`) и uplift@10% (`uplift_10_pp`) как описательные метрики.
- **Неопределённость:** 500 парных bootstrap выборок eval-строк с сохранением числа строк каждого treatment arm; внутри выборки пересчитать Q̂ каждого FM и классического метода, random-среднее считать по метрикам. 95% percentile интервалы условны на обученных моделях, контекстах и split; выводить их при ≥400 валидных выборках. Сначала разность внутри split, затем её среднее и число положительных split внутри датасета. Три split имеют общие исходные строки, а на Criteo меняется также исходная выборка. Формальную статистическую значимость и общий p-value не утверждать; шесть сравнений не использовать для выбора победителя без отдельного подтверждающего протокола.
- **Проверки входа:** SHA-256 пяти файлов CS01 на каждую комбинацию и обоих исходных parquet, уникальность/непересечение ID, точный порядок eval, treatment/outcome и конечность FM scores. При несоответствии остановиться до обучения; seed или строки не заменять.
- **Код:** [основной runner](../../../../src/m01_e02.py), [launcher](../../../../../../tools/run_m01_e02.py), [упаковщик](../../../../../../tools/package_m01_e02.py). Запуск из корня репозитория: `.venv/bin/python -u tools/run_m01_e02.py --check`, затем `.venv/bin/python -u tools/run_m01_e02.py all`. Для отдельного split вместо `all` использовать `101`, `102` или `103`. При повторе создаётся новый UTC run ID. Runner показывает этапы по датасетам, моделям и bootstrap.
- **Выход:** `artifacts/local/m01_e02_results/split_<seed>/<run-id>/` содержит полные предсказания S/T/X, метрики, парные разности, статус, протокол и копию исполнявшегося кода. При сбое статус `incomplete`. Git SHA, признак незакоммиченного runner и SHA-256 исполнявшегося скрипта записываются в протокол. После трёх завершённых запусков `tools/package_m01_e02.py --run-101 <путь> --run-102 <путь> --run-103 <путь>` создаёт неизменяемый компактный снимок в `results/E02/v001/<run-id>/`, проверяя исходные и новые Q̂ и хеши.
