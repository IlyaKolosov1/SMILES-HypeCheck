# M01 / E12 / v001 — известный CATE на ACIC 2016

- **Статус:** plan. Протокол и код фиксируются Git-коммитом до расчёта метрик моделей. Owner: команда M01.
- **Вопрос:** даёт ли CausalPFN добавочную ценность по точности CATE сверх прямого среднего исходов в **том же** feature-контексте, когда назначение treatment неравномерно и зависит от данных? Это проверка границы прежних RCT-наблюдений; она не означает, что FM гарантированно лучше.
- **Источник:** [ACIC 2016 challenge data](https://github.com/BiomedSciAI/causallib/tree/master/causallib/datasets/data/acic_challenge_2016) из репозитория `BiomedSciAI/causallib`, локально `artifacts/local/external/acic2016/`. Один `x.csv` (4 802 строки, 58 исходных признаков) и все десять опубликованных в этом зеркале `zymu_1.csv`…`zymu_10.csv`; исходные CSV и LICENSE в Git не добавлять. В каждом сценарии `z` — treatment, фактический train-outcome — `y1` при `z=1`, иначе `y0`; **истинный CATE** для оценки — `mu1−mu0`. Сценарии `2,3` имеют постоянный CATE и служат отрицательным контролем; `1,4–10` — восемь сценариев с неоднородным CATE. Ковариаты одни и те же, поэтому десять сценариев не являются независимыми реальными датасетами.
- **Разбиение и доступ:** один общий group-safe train/eval split по полному `x`, `GroupShuffleSplit(test_size=0.2, random_state=42)` (3 841/961 строка). Преобразования признаков обучать только на train. Моделям доступен только фактический train-outcome, treatment и train-covariates; `mu0/mu1`, контрфактические исходы и eval-outcome не подавать моделям/селекторам.
- **Контекст:** `K=512`, 256 control и 256 treated, feature-kNN отдельно по arms и три query-dependent random-контекста с seeds `41,42,43`; набор предобработанных признаков, budget и строки одинаковы для FM и прямого локального среднего. Зафиксированный CausalPFN checkpoint `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, без обучения FM. `T-Learner` — два `HistGradientBoostingRegressor` с `learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1.0`, `random_state=42`; настройка по eval запрещена.
- **Primary на восьми неоднородных сценариях:** PEHE = RMSE предсказанного CATE относительно `mu1−mu0`. Парные разности `PEHE(local feature)−PEHE(FM feature)` и `PEHE(T)−PEHE(FM feature)`; положительный знак означает лучший FM. Для сравнения масштабов каждую разность делить на `SD(true CATE)` соответствующего eval. Предзаданный **описательный ориентир** для дальнейшего независимого теста: FM лучше **обоих** методов минимум на `6/8` сценариев, средние нормированные разности против обоих больше `0.1`, а нижние границы условных интервалов средних больше нуля. Это не статистическое доказательство переносимости.
- **Secondary:** PEHE feature−mean(random) внутри FM и local; их interaction, абсолютная ошибка/разброс score на двух сценариях с постоянным CATE, oracle regret@10% по истинному CATE. Нельзя выбрать лучший из random seeds или поменять primary после просмотра результатов. Q̂ по наблюдаемым исходам здесь не primary: assignment симулирован и может быть confounded; истинный CATE позволяет прямую проверку.
- **Неопределённость:** 500 одинаковых bootstrap-ресемплов eval-строк на сценарий для парных PEHE-разностей, seed `14000+scenario`. Средние draw по восьми сценариям после нормировки дают **условный** интервал; общие `x`, фиксированный split и заранее выбранные сценарии не учтены как независимая случайная выборка.
- **Хранение:** полные score, truth, контексты и run-файлы — `artifacts/local/m01_e12_results/`, исключены из Git. Один неизменяемый компактный снимок `results/E12/v001/<run-id>/` с метриками, парными разностями, интервалами, входными и выходными SHA, кодом и Git SHA. При ошибке соответствующий сценарий получает `incomplete`; номер сценария не подменять. Старые результаты M01 и CS не менять.

Команды из корня: `.venv/bin/python tools/run_m01_e12.py --check` проверяет входы/разбиение/checkpoint; `.venv/bin/python tools/run_m01_e12.py --smoke` делает два FM-запроса без метрик eval; `.venv/bin/python -u tools/run_m01_e12.py all` считает все десять сценариев и упаковывает снимок; `.venv/bin/python tools/run_m01_e12.py --status` показывает стадии и сохранённый прогресс.
