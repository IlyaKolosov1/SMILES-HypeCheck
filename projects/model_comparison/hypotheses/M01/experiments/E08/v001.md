# M01 / E08 / v001 — новая проверка таргетинга верхних 10% на Criteo

- **Статус:** plan. Протокол выбран после просмотра M01/E06–E07, до чтения исходов новых когорт `407–409`. Criteo, бюджет 10% и T-Learner выбраны по предыдущим результатам. Поэтому даже положительный итог подтверждает только устойчивость на новых строках **этого источника**, а не универсальный эффект или непредвзятый выбор гипотезы.
- **Вопрос:** даёт ли treatment-balanced feature-контекст CausalPFN практически полезный прирост в верхнем дециле по сравнению с сильным классическим T-Learner и простым средним uplift по тем же соседям? Q̂ остаётся отдельной метрикой ранжирования и не подменяет этот вопрос.
- **Данные:** Criteo-ITE-v2.1, benefit outcome `visit`, те же десять очищенных `f*` признаков и закреплённые SHA parquet/metadata. Источник собран из рандомизированных рекламных тестов, перебалансированных к общей доле treatment около 85%; ID отдельных рекламодателей не опубликованы ([описание авторов](https://arxiv.org/html/2111.10106v1#S3.SS7)). Восстановить и исключить полностью старые 100k samples `42,301–303,401–406`, сверив последние шесть с сохранёнными `sample_rows.npy` и SHA. Из остальных source rows последовательно, без замены выбрать три **новые** выборки по 200 000 строк с seeds `407,408,409`. Не читать их `visit` до коммита кода и протокола.
- **Разбиения:** `(sample seed, split seed)=(407,117),(408,118),(409,119)`. Один group-safe split по одинаковым feature-векторам внутри каждой выборки, 51 200 train и 32 768 eval строк. Все модели получают одинаковые ID, T и Y. Preprocessing обучается только на train. При недостатке test-строк или пустой ячейке `T × visit` запуск остаётся `incomplete`, seed не заменять.
- **Методы:** CausalPFN `vdblm/causalpfn`, revision `83aad07da1cb077cfda4236878a1b07dc9f72a54`, CPU, `calibrate=False`, query-dependent feature-kNN `K=512`, по 256 control/treated на запрос. Прямое среднее train-`visit` treated минус control по тому же контексту. S/T/X-Learner из `m01_e02.fit_predict` с фиксированными `HistGradientBoosting` параметрами (`learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1.0`, seed `42`) и теми же train-строками; S и X — дополнительные ориентиры, T — заранее выбранный сильный классический comparator. Никакого подбора по eval.
- **Политика верхнего дециля:** для каждого метода и когорты выбрать ровно `ceil(0.1 × 32768)` eval-строк по score. При равенстве score порядок задаёт фиксированное 64-битное перемешивание `source_row` с константой `0x9e3779b97f4a7c15`; оно не использует T/Y и одинаково для всех методов. Сохранить selected-маску каждого метода и число treatment/control и событий в выбранной группе. `uplift@10%` — `100 × (mean visit | selected,T=1 − mean visit | selected,T=0)` в процентных пунктах. Переключение правила ties после просмотра результатов запрещено.
- **Primary:** два парных контраста `uplift@10%(FM feature) − uplift@10%(T-Learner)` и `uplift@10%(FM feature) − uplift@10%(direct local)` внутри каждой когорты. Главная сводка — равновесное среднее трёх разностей. Совместный **описательный** ориентир выполнен только если обе средние положительны, обе разности положительны в 3/3 когорт и нижние границы 95% условного bootstrap-интервала средних > 0. Если T или local выигрывает, нельзя объявлять преимущество FM над сильными baseline, даже при положительном FM−X.
- **Неопределённость:** 1000 парных bootstrap-повторов eval-строк с сохранением treatment arm внутри каждой когорты, seeds `9800+sample_seed`. Выбранные политики/маски фиксируются до bootstrap, затем переоценивается эффект среди выбранных строк; одинаковые resampled rows для всех моделей. Для среднего трёх когорт соединять draws по номеру и брать percentile 95% интервал. Интервалы условны на обученных моделях, этих train/eval и выборе Criteo по прошлым результатам; не дают междатасетного p-value.
- **Secondary:** FM против S/X, абсолютный uplift@10% всех методов, Q̂ (`normalized_qini_auc`), normalized AUUC, лечение/исходы и время. Отдельно показать, сохраняется ли Q̂-провал E06. Вторичные результаты не заменяют primary.
- **Хранение:** полные predictions, selected-маски, context IDs и промежуточные файлы — только в `artifacts/local/m01_e08_results/`; отдельная папка по каждой когорте, статус `incomplete` при прерывании, повторный запуск не подменяет seeds. После трёх завершений — компактный неизменяемый снимок `results/E08/v001/<run-id>/` с метриками, парными разностями, интервалами, SHA входов/выходов, Git SHA и SHA кода. Старые результаты не изменять.

До полного запуска выполнить `.venv/bin/python tools/run_m01_e08.py --help`, `--check`, `--smoke`, валидатор и зафиксировать код/протокол Git-коммитом. `.venv/bin/python -u tools/run_m01_e08.py all` затем считает когорты последовательно с однострочным прогрессом; `.venv/bin/python tools/run_m01_e08.py --status` только показывает стадию и сохранённый прогресс. После выполнения независимо сверить SHA, split, balance, score, маски, метрики и bootstrap. Примерное CPU-время — около часа.
