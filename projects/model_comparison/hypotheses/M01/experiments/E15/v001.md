# M01 / E15 / v001 — цена FM на том же контексте в большом Criteo holdout

- **Статус:** plan. Owner: M01. Код и этот протокол нужно закоммитить до просмотра новых score и policy-метрик. Один заранее определённый запуск; при неудаче seed, `q`, outcome и primary не менять.
- **Вопрос:** приносит ли замороженная CausalPFN добавочную пользу для таргетинга верхних 10% по сравнению с прямой локальной разностью средних на **точно тех же 256 control + 256 treated соседях**? Это проверка прикладного сигнала M01/E08, где FM−local по `uplift@10%` было `−3,412` п.п. на трёх новых, но малых когортах. Дополнительный аудит сохранённых строк нашёл лишь 57–67% совпадения выбранных пользователей; это объяснение пока разведочное.
- **Источник:** оригинальный Criteo Uplift v2.1 с `13 979 592` строками; бинарное назначение рекламы `T`, outcome `visit`, 12 входных `f0–f11`. Использовать прежние локальные `features.parquet`, `outcomes.parquet`, `cleaning_metadata.json`, checkpoint CausalPFN ревизии `83aad07da1cb077cfda4236878a1b07dc9f72a54`. Их SHA сверяет runner с M01/E08. Предыдущий [снимок E08](../../results/E08/v001/20261019T141726_397774Z/README.md) и локальные ID всех его трёх когорт проверить по manifest/SHA; вместе с прежними когортами E06 они исключаются из новой выборки. Поскольку источник Criteo ранее широко анализировался, это **новый непересекающийся holdout того же опубликованного источника, не новая независимая кампания**.
- **Фиксированные IDs:** `sample_seed=20261020`, равномерно без возвращения выбрать 650 000 source rows из оставшихся. `split_seed=20261021`: `GroupShuffleSplit(test_size=0.85)` по хешу полного вектора `f0–f11`; из его train/eval частей равномерно без возвращения взять соответственно 51 200 train и 500 000 eval. Оба множества должны существовать, не пересекаться по `source_row` и полному вектору признаков. Seed — только воспроизводимый идентификатор, без содержательного значения. `bootstrap_seed=20261022`. Порядок и SHA выбранных IDs сохранить.
- **Модели:** feature-kNN отдельно внутри каждого treatment arm, `K=512` (256+256), тот же train-only preprocessing для FM и direct local. Direct local = среднее train-`visit` treated-соседей минус среднее control-соседей. FM получает ровно этот контекст и зафиксированные веса без дообучения. Дополнительные S/T/X-Learner используют параметры M01/E02: HistGradientBoosting, `learning_rate=.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1`, seed `42`; преобразования обучаются только на train. Гиперпараметры и признаки не подбирать на eval.
- **Primary:** парная разность `uplift@10%` = `U(local_feature_mean)−U(feature_knn_K512)` в процентных пунктах на одних 500 000 eval-строках. `U(score)` — наблюдаемая разность долей `visit` между назначенными и контрольными внутри верхних 10% по score. При равном score порядок определяет фиксированный hash `source_row`. Условный 95% percentile-интервал получить из 1000 общих bootstrap-перевыборок **eval-строк внутри T-arm**, сохраняя исходные score и выбранные маски. Описательный ориентир практической важности: оценка `>+1,0` п.п. и нижняя граница условного интервала `>0`. Это один primary-контраст; порог 1 п.п. выбран до новой оценки как минимальный заметный прирост для 10% бюджета, без данных о денежной цене контакта.
- **Вторая основная метрика:** Q̂ (`normalized_qini_auc` из `sklift.metrics.qini_auc_score`) для тех же пяти score. У неё отдельный смысл — качество ранжирования всей кривой; статистический primary-критерий этой версии заранее закреплён только за `uplift@10%`, поэтому значение Q̂ и её направление сообщаются независимо от выполнения порога по `uplift@10%`, без заявления о подтверждённом приросте Q̂. Показать также `uplift@10%` и Q̂ S/T/X, FM−T/S/X и overlap выбранных множеств. Сравнение uplift у пользователей, выбранных только одним из двух методов, — вторичная описательная диагностика; отдельного утверждения о значимости для неё нет. Никакого PEHE: истинный CATE неизвестен.
- **Точность и цена:** сценарная экстраполяция условного E08 bootstrap на 500 000 eval даёт полуширину 95% интервала `≈0,83` п.п. и MDE 80% мощности `≈1,19` п.п. **Это планировочная оценка, не свойство будущего результата**; она не учитывает неоднородность новой когорты или повторное обучение. Локальный E08 FM занимал `1069` с на 32 768 запросов; линейно один FM-score на 500 000 займёт около `4,5` ч CPU плюс чтение данных, fit и bootstrap. Контексты считать и предсказывать блоками, показывать отдельные этапы, прогрессбар, выполнено/всего и ETA. Если ресурса не хватает, сохранить `incomplete` и возобновить тот же запуск, а не менять протокол.
- **Граница вывода:** исходный Criteo собран из нескольких incrementality tests с неравномерным downsampling; [авторы исправили утечку версии 1 в v2.1](https://ailab.criteo.com/criteo-uplift-prediction-dataset/), но ID кампании и её исходные propensity не опубликованы. Интервал условен на данный набор, train и замороженные модели. Даже успешный ориентир поддержит узкий вывод о прямой локальной оценке в этом источнике и бюджете; он не доказывает универсальную слабость FM. `feature_knn` против random-контекста в E15 не тестируется, поэтому E15 сам по себе не доказывает эффект выбора контекста.
- **Хранение и проверка:** `artifacts/local/m01_e15_results/<run-id>/` — полные предсказания, позиции контекста, IDs, логи стадий; `results/E15/v001/<run-id>/` — компактные метрики, парные разности, протокол, SHA всех входов/выходов, Git/code SHA и вывод. Сверить обработку ровно 500 000 eval-строк, отсутствие overlap, arm-balance всех контекстов, источники и manifest. Старые снимки не менять.

Команды из корня репозитория: `.venv/bin/python -u tools/run_m01_e15.py --check` проверяет источники и план IDs без обучения; `.venv/bin/python -u tools/run_m01_e15.py --smoke` проверяет короткий FM-инференс без новых eval-метрик; `.venv/bin/python -u tools/run_m01_e15.py all` выполняет расчёт и упаковку; `.venv/bin/python tools/run_m01_e15.py --status` показывает стадию; после прерывания — `.venv/bin/python -u tools/run_m01_e15.py --resume` продолжает тот же запуск.
