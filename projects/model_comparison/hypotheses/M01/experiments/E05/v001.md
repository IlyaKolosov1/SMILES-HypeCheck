# M01 / E05 / v001 — фиксированные S/T/X на внешнем Starbucks RCT

- **Статус:** plan. Протокол выбран после просмотра [CS01/E06](../../../../../context_selection/hypotheses/CS01/results/E06/v001/20261019T083837_511040Z/README.md), но **до** обучения классических моделей на Starbucks. Это разведочное модельное сравнение на уже использованных eval labels, не новое независимое подтверждение CS01.
- **Вопрос:** даёт ли CausalPFN с `feature_knn_K512` качество сверх фиксированного X-Learner на том же официальном train/test? Дополнительно проверить, как соотносятся S/T-Learner и прямое среднее исходов по тем же feature-соседям. CS01/E06 показал выигрыш FM над random-контекстом по Q̂, но не показал выигрыш FM над прямым локальным средним; поэтому **нельзя** приписывать весь прирост самой FM.
- **Источник и парность:** официальные Udacity/Starbucks `training.csv` (84 534 строк) и `Test.csv` (41 650), outcome `purchase`, treatment `Promotion=Yes`; SHA файлов и происхождение приведены в [аудите](../../../../../../docs/EXTERNAL_DATA_AUDIT.md). Сохранённые FM scores брать из завершённого CS01/E06 `20261019T083837_511040Z`, нового FM-инференса нет. До обучения сверить SHA исходных CSV, `predictions.csv`, train/eval IDs, точный порядок `ID`, treatment/outcome и конечность всех FM scores. При несовпадении остановиться; test не пересоздавать и не подбирать subset.
- **Признаки:** ровно `V1`–`V7` как в CS01/E06: `V1,V4,V5,V6,V7` one-hot, `V2,V3` стандартизованы; fit только на train, 18 координат. Проверить численное совпадение transformed X с CS01/E06. `ID`, treatment и outcome в базовые X не входят. S-Learner добавляет treatment к тем же X в своей outcome-модели.
- **Классические модели:** [фиксированная реализация M01/E02](../../../../src/m01_e02.py) S-, T- и X-Learner. `HistGradientBoostingClassifier` для исходов и `HistGradientBoostingRegressor` для pseudo-effect этапа X. Параметры `learning_rate=0.05`, `max_iter=200`, `max_leaf_nodes=31`, `l2_regularization=1.0`, `random_state=42`; без подбора по Starbucks train/test. X-Learner использует исходы противоположного arm и вес treatment из train.
- **Primary:** Q̂ (`normalized_qini_auc`) на всех 41 650 test строках, `Δ = Q̂(CausalPFN feature_knn_K512) − Q̂(X-Learner)`. Заранее заданный описательный ориентир `Δ > 0`; нижняя граница условного 95% bootstrap выше нуля была бы более сильным свидетельством внутри этой кампании. Сравнения с S/T не использовать для выбора «лучшего» классического метода по eval.
- **Secondary:** Q̂ FM feature минус S- и T-Learner, прямое локальное среднее feature минус X-Learner, FM mean(random) минус X-Learner; абсолютные Q̂, AUUC, uplift@10%. Для mean(random) усреднять **метрики** трёх context seeds, не score-векторы. 1000 парных bootstrap выборок test-строк с сохранением размеров treatment arms, seed `1201`; 95% percentile интервалы условны на фиксированных train/test, моделях и context seeds. Множественные secondary интервалы не считать подтверждающими.
- **Выход:** полный per-row CSV и статус в `artifacts/local/m01_e05_results/<run-id>/`; компактный неизменяемый снимок `results/E05/v001/<run-id>/` с протоколом, метриками, разностями, SHA кода/входов/выходов и ограничениями. При ошибке статус `incomplete`, исходный CS01/E06 не менять.

Из корня репозитория: `.venv/bin/python -u tools/run_m01_e05.py --check` проверяет входы без обучения; `.venv/bin/python -u tools/run_m01_e05.py all` запускает расчёт; `.venv/bin/python tools/run_m01_e05.py --status` показывает стадию. Код и протокол должны быть зафиксированы Git до вычисления новых Q̂.
