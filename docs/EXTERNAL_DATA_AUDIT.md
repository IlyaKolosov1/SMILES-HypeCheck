# Кандидаты для внешней проверки селектора

Проверка выполнена 2026-10-19 **до** запуска CausalPFN и просмотра метрик моделей на этих данных. Базовые частоты outcome по treatment изучены в рамках аудита. Сырые CSV остаются только в исключённом из Git `artifacts/local/external/`.

## Udacity / Starbucks promotion

- Первичный источник файлов: [упражнение Udacity](https://github.com/udacity/DSND_Term2/tree/master/portfolio_exercises/Experiments) и его [описание](https://github.com/udacity/DSND_Term2/blob/master/portfolio_exercises/Experiments/Starbucks.ipynb). В описании сказано, что промо в исходной обучающей группе назначали случайно. [Независимый разбор этих же 126 184 строк](https://www.hbs.edu/ris/Publication%20Files/24-034_73dcd8bc-6187-4c84-9a1f-5fc765b03181.pdf), приложение F.1–F.3, описывает рандомизированный эксперимент и проверку баланса признаков. Это отдельный источник от ранее использованных Hillstrom, RetailHero, LZD и Criteo.
- Файлы: `data/training.csv` (84 534 строк; SHA-256 `4d48190fd0d6a65d3874fa9a9ac79d89007579716366c2cfe140ae999088aa4f`) и `data/Test.csv` (41 650 строк; SHA-256 `f5607ca0b2f6a6580ee2085659387b45735e81b41cad97c756ba068fcc06a625`). Загружены из официального репозитория Udacity; локальный путь `artifacts/local/external/udacity_starbucks/`.
- В обоих файлах 7 анонимных признаков `V1`–`V7`, `Promotion` (`Yes`/`No`), бинарный `purchase`, уникальный `ID`. Пропусков, повторяющихся строк и пересечения ID между файлами нет. Доли treatment/control близки к 1:1; наибольшая абсолютная standardized mean difference семи признаков — 0.0145 в train и 0.0126 в test.
- В `Test.csv` всего 480 покупок из 41 650 строк. Это внешняя проверка с **редким outcome**: Q̂ и uplift@10% могут иметь широкие интервалы даже на всём test. Указанный Udacity test следует оставить целиком зафиксированным для оценки; протокол и primary контраст выбрать до первого просмотра предсказаний/метрик моделей на нём. `ID` не подавать модели.
- Полная процедура назначения и построения учебного деления train/test не опубликована. Это подходящий **внешний RCT-бенчмарк** для проверки направления эффекта, но редкость покупок и единственная кампания ограничивают силу и переносимость вывода.

## Lenta

- Источник: [документация scikit-uplift](https://www.uplift-modeling.com/en/latest/api/datasets/fetch_lenta.html); локальный `artifacts/local/external/lenta/lenta_dataset.csv.gz`, SHA-256 `b531544f6c072d22f232d91e20ffcaca265acf224e02687502a40e6d56135682`. Gzip проходит проверку целостности.
- 687 029 строк, 195 столбцов. `group=test`: 515 892 (11.01% `response_att=1`); `group=control`: 171 137 (10.26% `response_att=1`). Большие пропуски ожидаются у некоторых редких товарных категорий: максимум 72.2%.
- По историческому `response_sms` standardized mean difference между группами 0.198; по `response_viber` 0.069. Документация называет эти признаки долями ответов на **предыдущие** сообщения. Одновременно документация не подтверждает случайное назначение текущего treatment. Поэтому Lenta пока годится только для анализа чувствительности с оговоркой о возможном confounding, а **не** для независимого подтверждения причинного uplift. Статистический баланс сам по себе не доказывает рандомизацию.

Следующий эксперимент на Udacity следует зарегистрировать отдельным версионным протоколом; выбор варианта селектора зависит от завершённого CS04/E02, без просмотра uplift-результатов Udacity.
