# Кандидат для short paper: разделить признаки поиска и входа causal FM

**Статус на 20 октября 2026 года:** перспективный **вопрос**, не найденный алгоритм и не подтверждённый выигрыш политики. После [CS04/E05](../../projects/context_selection/hypotheses/CS04/results/E05/v001/20261020T165022_718458Z/README.md) гипотеза о постоянной пользе «дальних по шуму» соседей закрыта. Остаётся более общий вопрос: как совместно выбирать признаки для поиска контекста и для входа CausalPFN, когда часть столбцов не связана с исходом или эффектом.

[CS04/E06](../../projects/context_selection/hypotheses/CS04/results/E06/v001/20261020T171138_317614Z/README.md) закрыл только gate осуществимости train-only отбора на одной лёгкой synthetic-схеме: input top-8 восстановил 8/8 полезных признаков в 8/8 seeds, а retrieval top-4 нашёл не менее 3/4 модификаторов эффекта во всех восьми. FM в E06 не запускалась. Решение перейти к новому факторному тесту принято по заранее указанному gate; это не подтверждение конечного метода.

## Почему это возникло из данных

- В [CS04/E01](../../projects/context_selection/hypotheses/CS04/results/E01/v001/20261019T064211_090052Z/README.md) на одном бинарном DGP вход FM из 8 oracle-известных полезных столбцов дал среднюю CATE RMSE `0,0638` с 8D-kNN, а вход из 32 столбцов — `0,1118` с 32D-kNN или `0,1243` с 8D-kNN. Отбор строк и вход изменялись в части сравнений, поэтому это не чистый эффект алгоритма выбора признаков.
- В [CS04/E05](../../projects/context_selection/hypotheses/CS04/results/E05/v001/20261020T165022_718458Z/README.md) **при тех же строках контекста** переход с 32 на 8 oracle-известных признаков уменьшил среднюю RMSE CausalPFN `0,1873→0,1280` для near и `0,1987→0,1290` для far. При 32 признаках `far−near=+0,0114`, при 8 — `+0,0010`. Прямое локальное среднее с теми же строками имеет RMSE около `0,185–0,186`. Но DGP и контрасты выбраны после других CS04 результатов, а полезные признаки названы генератором, не выучены из train.
- В [CS04/E04](../../projects/context_selection/hypotheses/CS04/results/E04/v001/20261019T115526_827302Z/README.md) знак `far−near` был противоположным (`−0,0093`) на бинарной задаче. **Перенос направления retrieval не получился.** Нельзя представить E05 как подтверждение E04 или переименовать вторичный эффект удаления столбцов в primary E05.

## Проверяемая версия идеи

Возможный метод должен **до eval** выбрать два набора признаков: один для поиска соседей, другой для подачи в FM. Правило обучается только на train с честными внутренними folds; число входных столбцов, K, бюджет подбора и цена nuisance-моделей фиксируются заранее. Простой baseline — фиксированный весь вход и feature-kNN; oracle-известные 8 столбцов в synthetic служат лишь верхним ориентиром. Сильные контролы — тот же retrieval с прямым/скорректированным local и глобальный T/S-Learner, которым доступен тот же train bank. Primary для известного CATE: парная разность PEHE на **новом** DGP и oracle regret при фиксированном охвате. На реальном RCT primary должен быть заранее выбранный policy estimand с проверенной точностью; Q̂ — дополнительная ранжирующая метрика.

Следующая работа до нового FM-инференса: сравнить по train-only proxy хотя бы два заранее названных способа выбора признаков (например, cross-fit permutation importance для двух outcome-поверхностей и для их разности), зафиксировать один по внутренней validation, затем оценить на новом семействе, где полезные признаки **не передаются** методу. Критерий продолжения следует задать **до** просмотра этих score: метод должен улучшить и полный FM, и сильный классический baseline по выбранной primary цели; вторичный oracle gap показывает, сколько осталось недостижимого запаса. Если этого нет, не строить методическую статью вокруг feature selection.

## Новизна и границы

[CausalPFN](https://arxiv.org/html/2506.07918v2) уже исследует размер контекста и использует retrieval. [LoCalPFN](https://proceedings.neurips.cc/paper_files/paper/2024/hash/c40daf14d7a6469e65116507c21faeb7-Abstract-Conference.html) применяет локальный retrieval с fine-tuning. [Исследование TabPFN](https://arxiv.org/abs/2604.04868) сообщает устойчивость к нерелевантным признакам на своих классификационных тестах. Наши числа относятся к **CausalPFN и CATE** на двух специально построенных схемах, так что не опровергают выводы о TabPFN и не дают права заявлять «первое решение feature selection». Возможный вклад short paper — проверенное **разделение feature set для retrieval и feature set для FM** с сильными causal baselines и policy-метрикой. Пока это условный маршрут, а не установленная новизна.
