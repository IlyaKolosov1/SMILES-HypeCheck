# Кандидат для short paper: разделить признаки поиска и входа causal FM

**Статус на 20 октября 2026 года:** конкретный train-only метод с раздельными наборами признаков **не прошёл** предзаданный gate [CS04/E07](../../projects/context_selection/hypotheses/CS04/results/E07/v001/20261020T180541_845007Z/README.md). Вопрос о влиянии лишних входов на CausalPFN остаётся диагностически интересным, но этот маршрут пока не даёт методического результата для short paper. Гипотеза о постоянной пользе «дальних по шуму» соседей ранее закрыта [CS04/E05](../../projects/context_selection/hypotheses/CS04/results/E05/v001/20261020T165022_718458Z/README.md).

[CS04/E06](../../projects/context_selection/hypotheses/CS04/results/E06/v001/20261020T171138_317614Z/README.md) закрыл только gate осуществимости train-only отбора на одной лёгкой synthetic-схеме: input top-8 восстановил 8/8 полезных признаков в 8/8 seeds, а retrieval top-4 нашёл не менее 3/4 модификаторов эффекта во всех восьми. FM в E06 не запускалась. Решение перейти к новому факторному тесту принято по заранее указанному gate; это не подтверждение конечного метода.

[CS04/E07](../../projects/context_selection/hypotheses/CS04/results/E07/v001/20261020T180541_845007Z/README.md) проверил FM на другой функции: раздельный вариант лучше полного FM по PEHE на `0,08239` (8/8), но **чуть хуже общего выбранного набора** (`PEHE(shared)−PEHE(split)=−0,00028`, 5/8 положительных). Прямой local на тех же соседях точнее раздельного FM (`0,12035` против `0,13124` PEHE) в 8/8 и имеет меньший средний regret@10%. Условия против глобального T-Learner и по policy выполнены, но совместный критерий метода **нет**. Основной вклад в улучшение полного FM — train-only удаление шумовых входов, уже само по себе известный тип предобработки.

## Почему это возникло из данных

- В [CS04/E01](../../projects/context_selection/hypotheses/CS04/results/E01/v001/20261019T064211_090052Z/README.md) на одном бинарном DGP вход FM из 8 oracle-известных полезных столбцов дал среднюю CATE RMSE `0,0638` с 8D-kNN, а вход из 32 столбцов — `0,1118` с 32D-kNN или `0,1243` с 8D-kNN. Отбор строк и вход изменялись в части сравнений, поэтому это не чистый эффект алгоритма выбора признаков.
- В [CS04/E05](../../projects/context_selection/hypotheses/CS04/results/E05/v001/20261020T165022_718458Z/README.md) **при тех же строках контекста** переход с 32 на 8 oracle-известных признаков уменьшил среднюю RMSE CausalPFN `0,1873→0,1280` для near и `0,1987→0,1290` для far. При 32 признаках `far−near=+0,0114`, при 8 — `+0,0010`. Прямое локальное среднее с теми же строками имеет RMSE около `0,185–0,186`. Но DGP и контрасты выбраны после других CS04 результатов, а полезные признаки названы генератором, не выучены из train.
- В [CS04/E04](../../projects/context_selection/hypotheses/CS04/results/E04/v001/20261019T115526_827302Z/README.md) знак `far−near` был противоположным (`−0,0093`) на бинарной задаче. **Перенос направления retrieval не получился.** Нельзя представить E05 как подтверждение E04 или переименовать вторичный эффект удаления столбцов в primary E05.

## Проверенная версия идеи

Возможный метод должен **до eval** выбрать два набора признаков: один для поиска соседей, другой для подачи в FM. Правило обучается только на train с честными внутренними folds; число входных столбцов, K, бюджет подбора и цена nuisance-моделей фиксируются заранее. Простой baseline — фиксированный весь вход и feature-kNN; oracle-известные 8 столбцов в synthetic служат лишь верхним ориентиром. Сильные контролы — тот же retrieval с прямым/скорректированным local и глобальный T/S-Learner, которым доступен тот же train bank. Primary для известного CATE: парная разность PEHE на **новом** DGP и oracle regret при фиксированном охвате. На реальном RCT primary должен быть заранее выбранный policy estimand с проверенной точностью; Q̂ — дополнительная ранжирующая метрика.

E06 использовал train-only permutation importance двух outcome-поверхностей и R-loss для эффекта; E07 проверил полученные два набора на новой функции. Критерий разделения не выполнен, поэтому **не повторять FM-прогон с подогнанным числом входов, importance или seeds на этих же генерациях**. Возвращаться к ветке имеет смысл лишь с независимой причиной ожидать выигрыш именно от разных пространств, заранее выбранным сильным local-контролем и новой проверкой, не выбранной по E07 score.

## Новизна и границы

[CausalPFN](https://arxiv.org/html/2506.07918v2) уже исследует размер контекста и использует retrieval. [LoCalPFN](https://proceedings.neurips.cc/paper_files/paper/2024/hash/c40daf14d7a6469e65116507c21faeb7-Abstract-Conference.html) применяет локальный retrieval с fine-tuning. [Исследование TabPFN](https://arxiv.org/abs/2604.04868) сообщает устойчивость к нерелевантным признакам на своих классификационных тестах. Наши числа относятся к **CausalPFN и CATE** на специально построенных схемах, так что не опровергают выводы о TabPFN и не дают права заявлять «первое решение feature selection». Возможный вклад short paper требовал бы проверенного **добавочного эффекта разделения feature set для retrieval и входа FM** с сильными causal baselines и policy-метрикой; E07 этого не показал.

После дополнительного чтения граница новизны уже: [MALTS](https://jmlr.org/papers/v23/21-0053.html) и [Model-to-Match](https://arxiv.org/abs/2302.11715) учат важность признаков для causal matching; [FSRM](https://arxiv.org/abs/2009.06828) совмещает отбор признаков с представлением для matching. Поэтому даже положительное сравнение с полным FM не было бы новой идеей «отбирать признаки для поиска». E07 подтвердил именно эту проблему: улучшение полного FM есть, но добавочной пользы от двух разных пространств нет.

Текущие CS04 DGP имеют рандомизированное `T`. Для наблюдательных данных сокращение retrieval до модификаторов эффекта может отбросить конфаундеры; проверенный здесь selector нельзя переносить туда без отдельной проверки идентификации и overlap. Это ограничение области применения, а не отрицательный результат E07.
