# Criteo v2.1: точность возможного повторного policy-теста

**Статус на 20 октября 2026 года:** аудит мощности, без нового обучения или инференса FM. Это тот же источник, на котором уже просмотрены CS01, M01 и другие результаты. Новые строки из него не станут независимой внешней кампанией.

## Что проверено

Локальные `artifacts/local/data_A_cleaned/Criteo-ITE-v2.1/features.parquet` и `outcomes.parquet` содержат по **13 979 592** строк. При потоковом чтении обоих файлов порядок `epk_id` совпал на всех строках. Для `T` из features и `visit` из outcomes получено:

| Группа | Без visit | С visit | Всего | Доля visit |
| --- | ---: | ---: | ---: | ---: |
| Control, `T=0` | 2 016 832 | 80 105 | 2 096 937 | 3,8201% |
| Treatment, `T=1` | 11 305 831 | 576 824 | 11 882 655 | 4,8543% |

Доля treatment в **выпущенном файле** — `0,8500001`. Это не проверенная индивидуальная вероятность назначения. [Criteo AI Lab](https://ailab.criteo.com/criteo-uplift-prediction-dataset/) описывает рандомизированные incrementality tests, объединённые в одном источнике, и неравномерную подвыборку перед публикацией для сокрытия исходного incrementality. Авторы выпустили исправленную версию с 13 979 592 строками после обнаружения утечки между рекламодателями. В локальном `cleaning_metadata.json` ещё удалены два почти дублирующих признака; совпадающие feature vectors не удалены и требуют group-safe split. Эти условия ограничивают перенос результата на исходную популяцию рекламодателей и интерпретацию общей доли `T=1` как известной propensity.

Файлы и их SHA уже зафиксированы в [M01/E08 study protocol](../../projects/model_comparison/hypotheses/M01/results/E08/v001/20261019T141726_397774Z/study_protocol.json): features `a172c0c811c0f53826c797dc504bd47e7a2c58baa3b4390b6a4dd792d31d9464`, outcomes `dd864b66d2307132cecce7f5b39e7841ede3377d3313a875c6cffcdfb6abfa61`. Нынешний подсчёт использовал только столбцы `epk_id,T,visit`; индивидуальные score не создавались.

## Сценарная точность

Для **двух заранее фиксированных политик одинакового охвата** `q` пусть `r` — доля перекрытия выбранных ими людей. Доля строк, где политики различаются, тогда `2q(1−r)`. При *условном* допущении константной propensity `e=0,85`, независимых строк и одинаковых частот исхода в выбираемых/невыбираемых группах аппроксимация стандартной ошибки парной IPW-разности ценности политик во всей опубликованной популяции:

```text
SE ≈ sqrt{ 2q(1−r) [p1/e + p0/(1−e)] / n_eval }.
```

Здесь `p1=0,0485434`, `p0=0,0382010` — полные частоты visit по arms. `95%` полуширина равна `1,96 SE`; ориентировочная MDE при 80% мощности — `2,80 SE`. Это **плановый сценарий**, не доверительный интервал эффекта: исходы всего опубликованного файла уже видели в совокупности; фактические выбранные подгруппы, перекрытие, assignment propensity, зависимость и качество nuisance-моделей не проверены. AIPW может дать другую дисперсию.

Для Criteo уже был [M01/E08](../../projects/model_comparison/hypotheses/M01/results/E08/v001/20261019T141726_397774Z/README.md) с тремя новыми непересекающимися source cohorts и `32 768` eval-строками в каждой: FM проиграла фиксированному T-Learner по среднему uplift@10% на `1,485` п.п., direct local — на `3,412` п.п. Это **не** новое свидетельство этого аудита, а причина не тратить следующий FM-бюджет на поиск положительного Criteo seed. Прежняя метрика uplift среди выбранных людей имеет другой масштаб, чем приведённая выше разность ценности политик во всей популяции.

**Решение:** Criteo может уточнять точность и проверять конкретный заранее сформулированный механизм, но не заменит независимую кампанию для переноса и сам по себе не мотивирует ещё один многочасовой FM-прогон. При появлении нового train-only правила сначала зафиксировать primary policy и comparator, исключить все просмотренные source rows, проверить групповые дубликаты и основание для propensity; затем рассчитать мощность на нужном eval-размере и лишь после этого оценить ресурсы инференса.
