# Lenta: аудит пригодности для внешней проверки политики

**Статус: аудит завершён 20 октября 2026 года; подтверждающим RCT Lenta не назначать.** [Публикация файла в scikit-uplift](https://www.uplift-modeling.com/en/latest/api/datasets/fetch_lenta.html) указывает BigTarget Hackathon Lenta/Microsoft 2020, treatment/control, исход `response_att` (посещение магазина), 687 029 строк и признаки покупок до кампании. Процедура назначения treatment, вероятность назначения и единица рандомизации там **не описаны**. Даже хороший баланс наблюдаемых признаков не докажет случайное назначение.

## Решающий аудит до FM

Источник — уже сохранённый `artifacts/local/external/lenta/lenta_dataset.csv.gz`; скрипт `tools/audit_lenta_assignment.py`. Зафиксировать SHA, фактические столбцы/строки, пропуски `group` и outcome, число treatment/control, число событий каждого arm. Коды `group` должны быть только `test` и `control`, outcome — 0/1. Проверить, есть ли ID для исключения повторяющихся клиентов.

Для диагностики назначения взять фиксированную случайную четверть строк (`seed=2711`), исключить `group`, `response_att` и идентификаторы. 75% этой подвыборки использовать для fit, 25% — для проверки HistGB-классификатора назначения (`learning_rate=.05`, `max_iter=100`, `max_leaf_nodes=15`, `l2_regularization=1`, `random_state=42`); пропуски обрабатываются HistGB, категории `gender` кодируются только по fit-части. Показать AUC и максимальные абсолютные стандартизованные разности средних и долей пропусков по исходным признакам. **AUC >0,55** или явная концентрация больших дисбалансов — сигнал против простой константной propensity; AUC около 0,5 лишь совместим с ней, не подтверждает рандомизацию.

Планировочная точность: для двух фиксированных политик охвата 40% оценить 95%-полуширину парной IPW-разности на **половине** строк (остальные зарезервированы для train) при предполагаемой константной `e=P(T=1)` и трёх сценариях перекрытия выбранных множеств: 0%, 50% и 75%. Использовать наблюдаемые частоты события по arm только как оценку дисперсии Bernoulli. Это **условный сценарный расчёт мощности**, не confidence interval фактического эффекта, не разрешение считать propensity известной; `e` не брать за доказанную вероятность назначения.

Вывод audit-gate: если дизайн назначения не подтверждён документом организаторов, источник остаётся диагностическим benchmark даже при AUC≈0,5 и хорошей ожидаемой точности. Не запускать многочасовой FM ради «подтверждающего RCT» на основании одного наблюдаемого баланса. Если обнаружится предсказуемость назначения, дополнительно исключить упрощённый IPW с общей `e`. После аудита занести точные числа и решение в этот файл и [общий реестр источников](../EXTERNAL_DATA_AUDIT.md).

## Полученные данные и решение

Файл `lenta_dataset.csv.gz`: SHA256 `b531544f6c072d22f232d91e20ffcaca265acf224e02687502a40e6d56135682`, 144 735 744 байта, **687 029 строк и 195 столбцов**; отдельного ID клиента в фактическом файле нет. `test`: 515 892 строки и 56 813 посещений (`11,01%`); `control`: 171 137 и 17 555 (`10,26%`). Это сырые частоты, не причинная оценка эффекта. В обработанном файле не найдено неизвестных кодов группы или outcome.

В фиксированной подвыборке 172 086 строк классификатор назначения дал **AUC 0,5495** на отдельной четверти подвыборки (43 022 строки). Среди 193 исходных признаков максимальная абсолютная стандартизованная разность — **0,197** для `response_sms`, доли отклика на **предыдущие** SMS по [описанию поставщика данных](https://www.uplift-modeling.com/en/latest/api/datasets/fetch_lenta.html). Следующая — `response_viber`, **0,069**; у остальных числовых признаков максимум около **0,031**. Наблюдаемая разница в прошлом отклике не согласуется с простой моделью одинаковой вероятности назначения без дополнительного объяснения дизайна; AUC сама по себе только погранична к заранее заданному порогу `>0,55`. Это не доказывает, что назначение было неслучайным: возможна неизвестная стратификация или особенности обработки файла. Но **истинная propensity и единица рандомизации не установлены**, поэтому общую долю `test` нельзя выдавать за известное `e(x)`.

Если *условно* предположить константную вероятность назначения `0,7509` и 343 514 eval-строк, планировочная 95%-полуширина разности двух фиксированных политик охвата 40% составляет **0,224 / 0,158 / 0,112 п.п.** при перекрытии выбранных людей 0 / 50 / 75%; соответствующая приблизительная MDE при 80% мощности — **0,319 / 0,226 / 0,160 п.п.** Это сценарий при неподтверждённом дизайне, а не валидный CI или гарантия точности AIPW/IPW.

**Решение:** источник имеет достаточно строк для потенциально точной оценки, но не проходит gate идентификации. Не запускать FM на Lenta как подтверждающий тест и не интерпретировать разницу групп причинно до документа организаторов о назначении, вероятностях и клиентских единицах. Локальный полный JSON-аудит `artifacts/local/external/lenta/assignment_audit.json` включает SHA кода и источника, 15 крупнейших дисбалансов и формулу сценарной точности; большой CSV остаётся вне Git. Новый FM-инференс не выполнялся.

## Запуск и видимость

Код и план были закоммичены до расчёта (`a9fb855`). `.venv/bin/python tools/audit_lenta_assignment.py --check` проверяет схему и наличие файла; `.venv/bin/python -u tools/audit_lenta_assignment.py all` считает аудит; `.venv/bin/python tools/audit_lenta_assignment.py --status` читает статус без расчёта. TTY показывает один progress bar по строкам и стадию; без TTY — короткий статус раз в 20 секунд или на границе стадии. При сбое локальный статус `incomplete`; результаты остаются только в игнорируемом `artifacts/local/external/lenta/`. Фактическое wall-clock время около **10 секунд** на текущей машине; прежняя оценка 1–3 минуты была консервативной. Пиковая RAM отдельно не измерялась. Обученная диагностическая модель не сохранялась, потому что нужна только её AUC.
