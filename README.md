## Как устроен результат

`проект → гипотеза → эксперимент → версия протокола → запуск`. У гипотезы есть свой README, в `experiments/E01/v001.md` описан неизменяемый протокол, а в `results/E01/v001/<run-id>/` лежат его метрики, параметры, статус и `manifest.json`. Новый seed при том же протоколе создаёт новый запуск; изменение метода, данных, outcome, разбиения, бюджета контекста или основной метрики создаёт новую версию. Старые результаты не перезаписываются.

Общие правила: [работа с экспериментами](docs/EXPERIMENTS.md), [шаблон протокола](docs/EXPERIMENT_TEMPLATE.md), [карта гипотез](docs/HYPOTHESES.md), [указатель результатов](docs/RESULTS.md). [Текущее направление исследования](docs/RESEARCH_DIRECTION.md) связывает результаты двух проектов. Для командного обсуждения используйте [шаблон PR](.github/PULL_REQUEST_TEMPLATE.md).

Что и как было перенесено из прежней структуры, записано в [журнале миграции](docs/MIGRATION.md).

## Данные и запуск

Локальные данные и полные выходы находятся в `artifacts/local/` и исключены из Git. Компактные снимки результатов размещаются **внутри гипотезы**. Для macOS и Python 3.11 зависимости зафиксированы в [requirements-mac.txt](requirements-mac.txt).

Из корня репозитория после создания окружения и получения данных можно проверить адаптеры без загрузки весов FM:

```bash
python3.11 -m venv .venv
.venv/bin/python -m pip install -r requirements-mac.txt
.venv/bin/python projects/context_selection/src/multi_dataset_context.py --audit
```

`--audit` читает пять подпапок в `artifacts/local/data_A_cleaned/`. Полные команды и ограничения — в [руководстве эксперимента CS01](projects/context_selection/hypotheses/CS01/experiment-guide.md). Текущие результаты выбора контекста, сравнения моделей и смешения перечислены в README соответствующих гипотез; все выводы пока разведочные.
